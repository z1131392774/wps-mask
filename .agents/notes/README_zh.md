# 决策记录

*[English](README.md)*

决策记录是 agent 写给 agent 和维护者看的短文档。代码说发生了什么，文档说怎么用，决策记录说我们为什么这么选、否掉了什么、代价是什么。没有这份记录，半年后同一场争论会再来一遍，而手里的信息通常更少。

一条决策，一份记录。记录不是变更日志、任务清单，也不是教程。

## 存放位置与命名

记录放在 `.agents/notes/{lifecycle}/YYYY-MM-DD-topic-slug.md`。文件夹就是记录的状态，状态变了，记录就在文件夹之间搬家。日期是**首次提出**这个话题的日子，不是最后编辑的日子；其余的交给 git 记。

- **`proposed/`** —— 实现前评审过的，或还没动手的。
- **`implemented/`** —— 决策已落地。内容跟着实际存在的东西更新。
- **`rejected/`** —— 考虑过，否决了。只要它的理由还能挡住一次说得通的重复错误，就留着。

目录树就是清单。别加索引文件：它把路径抄一遍，还会让每处不相干的记录改动都变成合并冲突。

记录之间用相对 Markdown 链接互链，别只写编号或标题；这样链接熬得过搬家，也查得动。

## 什么时候写

决策的理由会活过这次 diff 时，把记录和决策写进同一次改动：结构选择、值得记住的否掉方案、兼容承诺、安全规则、将来还会翻出来争的权衡。

机械性修改、局部 UI 调整、测试一看就知道病因的 bug 修复、代码和文档已经讲清的事，不写记录。已经持有该决策的记录，更新它，别加第二份。

## 文件格式

前三行固定：

```markdown
# Note: <title>

Status: <proposed | implemented | rejected — one-line reason>
```

状态和文件夹一致，不带日期，不带括号补充。

正文用 `## Problem` 开头，写成不依赖解法也读得懂。之后按生命周期定。

**`proposed/`**

```markdown
## Problem
## Proposal
## Alternatives considered
## Acceptance criteria
## Risks
```

**`implemented/`**

```markdown
## Problem
## Decision
## Alternatives considered
## Consequences
```

`## Decision` 用现在时。已落地的记录里不放 `## Proposal`、`## Plan`、`## Acceptance criteria`：计划已经过去，它的清单要么做到了，要么没做到。`## Testing` 和 `## Deferred` 只要陈述当前事实，就可以留。

**`rejected/`** 保留提案时期的各节。结论在 `Status:` 那一行；正文是提案本身，冻住不动。

**每份记录都必须有 `## Alternatives considered`。** 每个真实考虑过的方案，加上它为什么落选，一段一个，粗体打头。记下决策却不记它赢过谁，正好招来这份记录要终结的那场争论。方案是记下来的，不是编的：理由真的丢了，用一句话说明，不要凭想象重建。

## 让已落地的记录保持真实

已落地的记录描述已经发布的现实，事实变了它也跟着变：文件改了名、包搬了家、默认值换了、机制换代。这些事实在改动它们的同一次改动里更新。决策本身不改写；决策变了的记录，标为 Superseded，绝不改写成它的反面。

继任者要取代一份记录，只有在保留了它全部独有的理由、替代方案、后果和未决问题时，才能把它并进来，然后删掉。部分作废时两份记录都留着，互相链接，仍然成立的事实逐条改正。

## 删除与否决

- 只记了小改动或机械性改动的已落地记录，连同指向它的链接一起删掉。
- 否决掉的记录，等它拦不住任何人会犯的错时，删掉。
- 小仓库不建冷冻博物馆。决策有历史价值，就从替换它的那份记录链过去，记录本身留在 `implemented/`。
- 别为了吵赢删记录。用理由更充分的记录作废它，并在新记录里写清什么改变了你的想法。
