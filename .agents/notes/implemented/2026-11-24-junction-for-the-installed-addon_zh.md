# 决策记录：用目录联接代替复制加载项

Status: implemented

*[English](2026-11-24-junction-for-the-installed-addon.md)*

## 问题

WPS 从 `%APPDATA%\kingsoft\wps\jsaddons\wpsmask_1.0.0` 加载加载项，这个路径在仓库外面，所以每次改代码都要手工复制一遍。由此出过两种错。忘了复制，表现和「改了没修好」一模一样：旧行为照旧出现，而代码其实已经对了。另一种是反过来直接改装好的那份——改一行试试，这是最自然的做法——结果得到一个没有版本管理、下一次整份复制就会被覆盖的改动。

## 决定

`tools/link-addon.ps1` 把装好的文件夹做成指向工作区的目录联接，两边就是同一份文件。它先把已有的真实文件夹改名成 `wpsmask_1.0.0.bak-<时间戳>`，再校验 `js\engine.js` 能透过联接读出来；`-Rollback` 删掉联接并把备份还原。于是从改完到生效只剩重启 WPS 一步。

## 备选方案

**软链接。** 否决：创建软链接要么要管理员提权，要么要开发者模式，脚本会在普通 Windows 账户上失败，报的还是跟加载项毫无关系的错。

**硬链接。** 否决：硬链接只对文件存在，文件夹没法硬链接，那样就得逐个文件链、再手工维持这份清单。

**`wpsjs debug`。** 只作为唯一路径否决：它要 node 工具链，而本仓库刻意做成纯文件、复制即装。手册里仍保留给已经装了 `wpsjs` 的人。

**按需复制的同步脚本。** 否决：仍然是两份副本，而且只对记得跑它的人有用——那正是原来的问题。

**在 `jsaddons` 里改完再拷回来。** 否决：装好的文件夹不是工作目录，没有历史，版本号一改就消失。

## 后果

建立或回滚联接时必须关掉 WPS，因为加载中的加载项占着文件夹，改名会失败，脚本在那条报错里已经写明。`publish.xml` 仍需一次性复制，它描述该目录下所有加载项，脚本不能去改它。工作区搬家会让联接悬空，再跑一次即可。`.bak-<时间戳>` 文件夹在确认联接可用之后可以删掉。
