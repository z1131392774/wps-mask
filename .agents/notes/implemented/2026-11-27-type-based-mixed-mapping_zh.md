# 决策记录：混合列按 JS 类型映射，不按形态

Status: implemented

*[English](2026-11-27-type-based-mixed-mapping.md)*

## 问题

真实的账号列常常混排格式：一行手机号、一行邮箱、一行固话、一行带前导零的编码。[按形态映射的决策](2026-11-24-mixed-shape-columns_zh.md)给出的答案是逐格形态分类：`shapeOf()` 识别手机号、邮箱、固话、纯数字、字母数字或文本，`genMixed` 用每族一个生成器保住形态。形态合法性是保住了，代价是它成了引擎里最绕的分支——五条形态正则、五个形态生成器、文档里一张形态表、每种形态各自的「形态空间」容量报错，还有 `AGENTS.md` 里「每加一种形态就是一份契约」的常驻规则。

形态保真不是需求。脱敏只要求这个值不再等于原值；测试数据不需要通过原值当初要过的生产校验。按内容分类也正是加载项要戒掉的事：列模式本来就按 JS 类型选，混合分支里再塞一个基于正则的分类器，等于把「智能猜内容」又请了回来。每一条正则都是一个兜底口：不常见的值悄悄落到文本，文档还得负责解释为什么。

保形态还会跟宿主自己的解析打架。常规格式单元格会解析数字形状的文本：真机上 `008081` 会变成 `8081`、`1.20` 变成 `1.2`、`2024-01-01` 变成日期序列、`50%` 变成 `0.5`、`1,234` 变成 `1234`、`=1+1` 变成公式。旧纯数字生成器产出的 `000123` 这类假值，恰好就是宿主会静默转换的文本，所以「形态保住了」只在值跨过单元格边界之前成立。把文本按文本写回去需要宿主的文本标记（前导单引号）；旧反映射路径加了标记，写入失败后的回滚路径却没加。

本次改动的第一版缺了两块，审阅提交 `a76abd7` 后它们变成决策的一部分：

- `writeMask` 的失败分支直接写原始值：一批写入在写下 `008081` 之后失败时，回滚会把它写成数字 8081，随后区域记录又被重置，用户连「反映射」这条恢复线索都没了。
- 旧混合桶（来自已被取代的那篇记录）里存着数字字符串假值，宿主早已把它们存成数字。它们靠 loose 索引才能被还原，但没有任何机制阻止新生成的数字假值占用同一个数值：反映射先命中新的 typed 记录，于是把旧格静默还原成别人的原值——保存文档之后不可逆。

## 决定

保留三种列模式——数字、文本、混合——把「混合」定义为「同时存在两种 JS 类型」，而不是「有很多形态」。映射按 `typeof` 分派，绝不看内容：

| 值 | 映射后的值 |
| --- | --- |
| number | 从本列数值区间取的 number，保留本列小数位 |
| string | 字段名 + 数字，且保证含非数字字符，宿主不会把它转成数字 |

删掉 `shapeOf()`、手机号/邮箱/固话/字母数字/纯数字形态生成器和形态表；`genMixed` 只保留一个按类型分派的薄壳：数字交给 `genNumber`，其余交给 `genText`。`guessMode()` 不再因为形态而回落到 mixed。一个混合列由实际出现的 JS 类型决定，和数字列、文本列同一套规则。后续批次追加数字、而已记录假值占满本列数字槽位时，`prepareMask` 会只往上扩 `num.max`，直到 `slots - occupied >= max(需要+1, ceil(需要*1.1))`；区间真的装不下这批值时仍然大声报错，而不是复用假值。

反映射时所有字符串原值走 `textForWrite()`：非空字符串（不足 32,767 字符）加前导 `'`，宿主按文本存储且保持常规格式，读回时不带标记。`008081` 仍是 `008081`，`000123` 仍是 `000123`。

写入失败的回滚走同一条路径。`writeMask` 用文本标记写回原值，所以中途失败的一批不会把带前导零的文本变成数字。回滚本身也失败时，不调用 `restoreMaskBase()`：区域记录退回映射前的那一份，每个失败列再加一条 `partial` 记录——逐行计划假值、原值对应的桶键，加上本列签名——标记整体保留作为受损提示，所以回滚成功的列可能暂时留着紫边，直到下次反映射。反映射对这些记录逐格核对：当前值等于该行计划假值才写回原值，其余不动并计入 `skippedPartial`；快照核对过就置空。这些格子绝不走桶反查，所以某个值即使恰好等于同列别的行的假值，也不会被改写。两阶段映射本身不变（见[两阶段映射](2026-11-24-two-phase-mask_zh.md)）。

边框改用 `BorderAround`：一次调用只画四条外边，内部网格线不动。`vault.marks` 在写任何单元格之前记下每条边的原样式、线宽和颜色，去边框时写回；标记色是打包整数 `15547004`。真机上 8,240×3 的区域画一次 203 毫秒、清一次 79 毫秒，逐边给 `Borders` 赋值要 325 毫秒；混合边的样式宿主表达不了，所以未知的边一律不画。刷新时过滤范围没有任何记录匹配（异表、非法矩形）会退回整表重画，而不是静默什么都不做。边框与记录各有自己的记录（[标记边框](2026-11-25-marker-outline_zh.md)、[`marks` 不需要升版本](2026-11-25-marks-without-version-bump_zh.md)）。

批量映射、反映射和清表都在 `MaskQuietHost` 里跑：关屏幕刷新、手动重算、关事件，全部在 `finally` 里恢复。要不要恢复，看赋值之前是否读到了原值并准备赋值，而不是看赋值后的读回——COM 忙时读回可能抛错或返回旧值，让宿主停在手动重算等于坏掉整个会话；多写一次原值没有副作用。功能区快捷操作成功时是常驻状态栏提示，末尾追加 `。耗时 N 毫秒/秒。`；面板用自己的状态行；失败仍然是弹窗。

vault 保持版本 2，`sigOf()` 公式不变。没有任何键改变含义，`ranges` 与 `marks` 是可选字段、默认 `[]`，旧的 v1/v2 文档、phone 桶和 mixed 桶都仍可读、可反映射。上面的 loose 碰撞不靠迁移解决：`buildIndex()` 同时保留 typed 索引（`n:`/`s:`/`b:`）和 loose 索引，`prepareMask` 现在把 `keyOf(假值)` 与 `looseOf(假值)` 都登记进 `used`；`genNumber` 两种形态都查，于是新数字假值永远不可能占用旧假值（被宿主强转后）已经占着的值。反映射仍先查 typed、再查 loose。旧桶按原样复用，所以旧文档重新脱敏后仍可能保留旧形态假值——这一点写进行为文档，不藏。

phone 模式现在是遗留：自动识别不会再返回它，只有旧文档里保存的设置还能选中它。它的假值是数字字符串、在常规格里会被宿主存成数字，反映射靠 loose 索引还原；退役它是后续改动的 P2，需要自己的版本升级与迁移，不在本次范围。

## 考虑过的其他方案

**修好形态生成器、保留形态分类。** 否掉了：那要留下六个生成器、六条正则、每族各自的容量报错和文档里两段形态规则，只为保住一个脱敏数据并不需要的性质。按类型的规则更小、一句话能讲清，而且产出的值从构造上就不可能长得像原值。

**在面板里让用户逐值选形态。** 否掉了：活儿推回给用户，两百个账号要两百次选择，而需求本来就是自动处理混合列。

**取多数类型、接受损失。** 否掉了：产出的数据会在下游校验里失败，而且真正的混合列没有一个值得信任的多数。

**把 `VAULT_VERSION` 升到 3，把 mixed 与 phone 桶迁移成 typed number。** 本次否掉了：登记 loose 键就能消除碰撞，不用重写任何 vault，旧桶仍是合法的映射记录、签名也不变。版本升级留给真正的格式变更，比如退役 phone 模式；真要退役时，迁移随升级一起落地。

**回滚继续直接写原值，靠读回校验兜底。** 否掉了：读回失败可以报错，但没法把宿主已经丢掉的前导零变回来。这种损失必须在写之前避免，而不是写之后检测。

**继续逐边给 `Range.Borders` 赋值。** 否掉了：在实测区块上更慢，而且会画到内部线；BorderAround 一次调用且内部线不动。

**靠赋值后读回属性来决定是否恢复安静的宿主设置。** 否掉了：让读回失败的那种 COM 忙状态，恰恰可能让属性卡住；写之前记下的意图才是唯一安全的依据。

## 后果

引擎去掉形态分类器、五个形态生成器和形态表，`genMixed` 只剩按类型的两个分支；行为文档、`AGENTS.md` 和 README 都改为按类型描述脱敏。映射结果不再像原值——这个取舍写进行为文档和排错表，而不是糊过去。

旧文档继续可用：vault 版本不动、签名匹配、phone 模式的假值经 loose 索引还原、复用的混合桶可能保留旧形态假值。新文档里只有按类型生成的假值。loose 键登记、文本标记回滚与失败列的 `partial` 快照由本地 mock 覆盖，包括常规格式强转和注入的写入失败；宿主对数字形状文本的 `'` 行为此前已真机量过（`'008081` 保持字符串、格式仍是常规），但回滚路径、`partial` 快照与 loose 碰撞修复还没有真机复跑，验证页如实标为 mock 覆盖。

失败列契约替换的是更早一版「回滚失败保留全部区域记录」的做法。独立复核发现那版会把回滚成功列的原值也改写——某个值恰好等于同列别的行的假值时会被还原成那一行的原值——于是改成按列隔离加逐格快照，mock 现在覆盖了这个回归场景。

形态分类表不再是契约。加一种模式现在是类型层面的决定，而不是再加一个生成器；[被取代的记录](2026-11-24-mixed-shape-columns_zh.md)保留下来，作为形态分类表和它暴露的两个生成器缺陷的历史记录，不再代表当前行为。
