# 决策记录：先问宿主，别猜

Status: implemented

*[English](2026-11-25-live-probe.md)*

## 问题

本仓库所有测试都跑在 `test/mock-wps.js` 和 jsdom 里的真实面板页面上。而手册列了七条只有宿主能回答的行为——`publish.xml` 会不会被接受、任务窗格拿不拿得到 `window.Application`、`CreateTaskPane` 收不收 `file://` URL、`Worksheets.Add(undefined, 末表)` 返不返回工作表、隐藏表存盘后还在不在、十万行什么手感、受保护与合并单元格怎么表现——每一条都可能逼出一处代码改动。之前功能区那部分是手跑的十六个用例，既不能重复，也没法评审。

## 决定

真机自动化从探查开始，不从场景开始。

`tools/live/wps-bridge.ps1` 是一个长驻的 PowerShell 进程，按行收发 JSON：stdin 收 `{"id","op","args"}`，stdout 回 `{"id","ok","data"|"error"}`。它只负责 COM，别的一概不做——开工作簿、读单元格、用 engine 同一形态建表并隐藏、存盘、关掉、重开、加保护、合并、建窗格、给一次十万行写入和整片读回计时。

`tools/live/rpc.mjs` 是传输层的 Node 侧：分帧、按 op 计时超时、id 配对、桥退出时把未决调用全部拒掉。它刻意只做传输，这样才能用假管道和一个真子进程覆盖测试。

`tools/live/probe.mjs` 按依赖顺序问那七个问题，一行一个答案，用固定的五个词：`OK`、`NO`、`UNK`（宿主答了但没答到点上）、`MANUAL`（没有程序通道）、`SKIP`（要加 `--ui` 或 `--perf`）。末尾打印一张「条目 → 结论」表，就是给手册回填用的。

两条规则让这个探查可以被交给用户跑：只往自己新建的临时工作簿里写，绝不碰已经打开的文档；只关自己开的那些。判定全在 Node 侧，PowerShell 里不写结论。

## 考虑过的其他做法

**先把「映射—反映射」整条流程用功能区点通，再回头补探查。** 否决：`invoke` 能不能用，取决于 `CommandBars` 暴不暴露加载项控件，而那正是未验证清单的第 1 条。在答案出来之前写场景，要么卡在第一次点击，要么写死一个假设，然后被探查推翻。

**全部走 UIAutomation。** 否决：元素树和坐标会随语言、DPI、主题漂移，最终每条断言都变成截图对比。UIA 只保留一个很窄的退路——`CommandBars` 什么都不说时，用它回答「功能区到底存不存在」。

**每次调用都起一个 `powershell -Command`。** 否决：进程启动比大多数操作本身还贵，十万行的计时会变成在量 PowerShell；而且 COM 状态活不过两次调用，每步都得重开工作簿。

**在 Node 侧用原生 COM 绑定（`winax`、`edge-js`）。** 否决：每个 Node 版本都要重新编译原生模块，而加载项本身的承诺是零依赖。jsdom 已经是唯一的 devDependency，为了跑测试再引一个原生模块，会让测试比产品更难跑起来。

**把断言写进 PowerShell。** 否决：那样分帧、超时、桥退出只能装在 WPS 的机器上验。判定留在 Node，才让 `test/rpc.test.mjs` 用假管道和一个真子进程把这些都覆盖掉。

## 后果

第 2 条是这个探查最弱的一环。任务窗格里有没有 `window.Application`，从窗格外面没有程序通道，所以探查弹出的页面会直接把答案写成一行字，结论标成 `MANUAL`。必须有一个人看一眼；另一种做法是假装截图检查就是断言，那更糟。

记录仍是手工的：探查输出要人抄进手册。没有脚本去改那张验证表，所以表可能过期——这一点写进了手册，也写进了这里。

探查崩在半路会留下状态：清理放在末尾跑，临时工作簿可能开着。这看得见、也无害；另一种做法是在 COM 上套 `finally` 逐项清理，而那种清理自己就会抛。

头两次运行落实了四条，也产出了三个错误结论，全是我的：单格读回被折成裸字符串后按字符串取了首字符、`KetMainFrame` 是这台机器上根本不存在的类名、`CreateTaskPane` 不在 COM 对象上却被记成"宿主不支持"——它其实在加载项自己的 JS API 面上。现在每条结论旁边都打原始读回值，第三个错误就是这么看出来的。

这次运行也改了产品：只读文档会静默吞掉 `Save()`，映射表可能"保存成功"地丢掉，engine 现在在保存之前就拒绝。

测不了的部分现在也知道了。加载项的按钮从外部点不到——`CommandBars` 里没有，UIA 也列不出选项卡，因为 WPS 的功能区是自绘的——晚绑定又送不进数组，所以十万行计时和窗格那两条只能在加载项内部回答，或者由人点。那是下一层，不是这一层的漏洞。
