# 决策记录：面板按工作表和列位置记住手工改动

Status: implemented

*[English](2026-11-24-pane-config-memory-by-position.md)*

## 问题

面板每次选区变化都会重新读取并重建卡片。为了在重建时保留用户改过的参数，它按列的表头做快照。于是出现两种串列：无表头的列表头都是空字符串，所有无表头列看起来是同一列；两张工作表可以有同名表头（如「姓名」），在一张表改过的数值区间会被带到另一张表——带过去的区间可能装不下新表的值，于是报容量错误，或者同一批人拿到另一套假值。

## 决定

快照的键改成工作表名 + 列位置（`cfgKey(sheetName, col)`），并且只保留用户真正改过的列（`state.edited`）。没动过的列重新走 `hydrate()`，让它们取到属于当前选区的那份记忆设置。整块刷新——换选区、「重新识别」、删除映射表——先清空 `state.edited`。

## 考虑过的其他方案

**按表头记。** 否掉了：就是上面的串列。

**只按列序号记。** 否掉了：两张表列数相同时，切表会把设置带过去。

**不保留改动，让用户重填。** 否掉了：面板会随选区变化刷新，手一抖就丢掉全部参数，面板没法用。

**把快照存进保险箱。** 否掉了：保险箱是文档状态，而这些是尚未确认的界面改动；写进去等于把选区上的临时参数带进文档。

## 后果

重命名或插入一列会让该列丢失本次会话的改动、按保险箱重新推导——这是安全的方向。面板第 [14]、[15] 组钉住无表头和两张表同名表头两种情况。文档级记忆设置仍按表头存（`rememberSettings`），因为那是要跟着字段跨选区走的；只有会话内快照改用位置。
