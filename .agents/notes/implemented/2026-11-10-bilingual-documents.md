# Bilingual documentation

*[中文](2026-11-10-bilingual-documents_zh.md)*

## Problem

The team writes in Chinese and reads in Chinese, but every agent-facing document in this repository is English. Two bad outcomes follow. A reader who is not fluent in English works from a document they only half understand, and a translated copy that lives somewhere else drifts from the source until nobody knows which one is true.

## Decision

English stays the source, and each document is paired with a Chinese twin beside it: same stem, `_zh.md` suffix, both files linking to each other. `scripts/check-docs.mjs` fails when a twin is missing or when the pair no longer links, so a half-translated tree cannot be committed. A twin is measured in units — one per CJK character plus one per Latin word — against the English budget times `zhMultiplier`, because a faithful Chinese rendering is longer than the English it comes from.

## Alternatives rejected

- **Chinese first, English twin.** The agents that read `AGENTS.md` load an English preamble from their harness; keeping the source in the same language as the model's instructions removes a translation step from the layer that must never be wrong.
- **One file with both languages.** Doubles every file's length and makes the budget meaningless; a reader also has to skip half of every document.
- **Translation as a release step.** Drift accumulates between releases, and the gate cannot see it while it is cheap to fix.
- **Machine translation without review.** Word-order calques appear as soon as the subject is long; the Chinese reads as English wearing Chinese words. The writer translates, the gate checks the shape.

## Staleness is a separate failure

A pair that exists, links both ways, and fits its budget can still be wrong: the English half moved and the translation did not. The first gate version could not see this, and it cost a reader a confusing afternoon, so `check-docs.mjs` now compares the last commit that touched each half and reports the pair when the Chinese one is older. `pendingTranslations` in `doc-budgets.json` is the escape hatch for a rewrite spread over several commits. Repositories without history — a packed tarball, a shallow CI checkout — skip the comparison rather than guess; CI therefore checks out with `fetch-depth: 0`.

## Consequences

Every documentation change doubles its file count and costs a translation. In exchange, a Chinese-only reader gets a document written for them, and the gate makes a missing or stale twin visible before review rather than after.

Documents generated by tooling stay single-language through `excludePairs`; everything hand-written is paired.
