## 真机实测

WPS 表格 12.1.0.29161，`tools/live/probe.mjs` 加一次人工点开的面板，2026-11-25：

| 条目 | 结论 | 依据 |
| --- | --- | --- |
| 功能区出现「数据脱敏」 | 通过 | 看得到选项卡，`publish.xml` 被接受 |
| 任务窗格里的 `window.Application` | 通过 | 面板列出选区字段（`mask-small.csv!A1:C11`・10 行・3 列・首行是表头），并完成一次映射与一次反映射：三列都变成假值，原值又都回来了。取宿主对象先试 `window.Application`，取不到才退到 `wps.WpsApplication()`；两条通道没有分开探测 |
| `CreateTaskPane` 收 `file://` | 通过 | 面板由加载项目录自己的 `file://` URL 打开，标题与内容都正常渲染 |
| `Worksheets.Add(undefined, 末表)` | 通过 | 用 `Missing` 送参即可，新表建在末尾 |
| 隐藏表存盘重开 | 通过 | `Visible = 2` 保留，密文原样读回 |
| 十万行级性能 | 通过 | 10 万行单列点「快速映射」，约 7 秒后端到端完成（含建表、写密文、整列写入与读回校验），隐藏映射表同时建好（`Visible = 2`）；10 行 × 3 列走同一条链路 |
| 受保护工作表写入 | 通过 | 被宿主拒绝，engine 回滚并报错 |
| 合并单元格写入 | **注意** | 写合并区非锚点格不报错也不生效，engine 靠读回校验发现并回滚 |
| 只读文档保存 | **注意** | `Save()` 不抛错也不写盘；engine 现在在保存映射表前就拒绝 |

**单独一条结论：从外部点不到加载项按钮。** `CommandBars` 的 186 条里没有它的控件，UIA 也列不出选项卡（WPS 的功能区是自绘的）。真机自动化不能靠模拟点击；面板是能用的入口——人工点开一次后，上面的结果都是这么量出来的。

复现用 `npm run live:probe:log`：它只在自己新建的临时工作簿里写，不碰你已打开的文档；跑完把结果写进 `probe.log`。桥（`tools/live/wps-bridge.ps1`）只搬运和取数，判定全在 Node 侧，所以「一行拆成两段」「噪音行」「超时」「桥中途退出」这些传输行为由 `test/rpc.test.mjs` 覆盖，不需要 WPS。

## 常见问题

| 现象 | 排查 |
|---|---|
| 功能区没有「数据脱敏」 | 目录名必须是 `wpsmask_1.0.0`；`publish.xml` 的 `version`/`url` 要和目录名一致；改完必须重启 WPS |
| 面板空白、提示「未取到 WPS 应用对象」 | 任务窗格没拿到宿主对象：对照上节第 2 条 |
| 第一行没有被脱敏 | 它被当成表头了：要么勾了「首行是表头」，要么自动识别猜成了表头。取消勾选让第一行当数据处理，或把选区下移一行 |
| 反映射只还原了一部分 | 只还原记录过的区域，第二次点击是空操作。要用当初映射的选区还原；每个区域保留映射当时的签名，之后改该列参数不影响还原；同一个假值属于两个原值时会被跳过并计入 `有歧义` |
| 保存映射表时弹出失败提示 | 映射表在写单元格之前保存，保存失败时选区一格都没动，重新执行一次映射即可；提示里说「回滚未完成」时，先检查该区域再重试 |
| 提示「映射表损坏，已用备份恢复」 | 主密文损坏，已用备份列恢复。保存一次工作簿把主密文换掉；反复出现就改用备份副本 |
| 重新映射某列却没有变化 | 该列已经是映射结果，被跳过了。要按当前值再映射一遍，先「反映射」 |
| 反映射第二次没有反应 | 第一次反映射已经把记录裁掉了，这是设计上的空操作；要重新获得记录，再映射一次 |
| 数字列被显示成左对齐文本 | 目标单元格原本是文本格式，映射写入的数值保留了该格式，改单元格格式即可 |
| 提示「装不下 N 个不同值」 | 整数区间里放不下这么多不同值（如 12 个不同金额却只给 1~5）。自动映射会按数据范围扩区间，正常不会出现；只有你手改窄了区间才会，放宽范围或改小数位 |
| 提示「文档是只读打开的」 | 只读文档上保存会被静默忽略，映射表存不进去，脱敏后无法还原。先把文件另存为新文件再脱敏 |
| 提示「写入后读回不一致」 | 某一格写进去没落住。选区里有合并单元格是最常见的原因（写合并区的非锚点格不报错也不生效），先取消合并再重试；受保护的工作表也会这样 |
| 提示「解密失败」 | `KEY_TEXT` 被改过、隐藏表被手工编辑过，或主密文与备份都损坏；用保存过的文档副本恢复 |
| 混合列里某个值被映射成了「字段名+数字」 | 它不属于那五种形态（中文、只有一个字符、`2024abc` 这类数字开头的编码、或带 `_ . -` 和空格之外的符号），因此使用文本兜底——兜底同样一对一，也能还原 |

## 缺失的参考资料

按重要性排序。补齐后，上面标注「待验证」的条目可以改为实测结论：

1. **《WPS 加载项开发》整体**：`wpsjs` 工具链（`create` / `debug` / `build --exe` / `publish`）、工程目录规范、`publish.xml` 与 `jsplugins.xml` 两种部署模式、离线 `.7z`/`.exe` 打包规则、宏与加载项的权限/信任差异。
2. **`ribbon.xml` 规范**：可用控件（tab/group/button/toggleButton/dropDown/menu/…）、全部回调及其签名（`onLoad`/`onAction`/`getImage`/`getEnabled`/`getVisible`/`getLabel`/`getScreentip`…）、`imageMso` 取值表、`2006/01` 与 `2009/07` 两个命名空间的行为差异。
3. **网页侧 JSAPI 与宏 API 的差异清单**：`window.Application` vs `wps.WpsApplication()`、`Range.Value2` 的数组形状与**跨上下文数组**（`instanceof Array` 失效，这个差异曾导致引擎的一处 bug）、`Selection`、`CreateTaskPane`/`GetTaskPane`/`ShowDialog`、`PluginStorage`、`ApiEvent`、`OAAssist`、任务窗格与宿主页之间的通信方式。
4. 加载项里的异步/同步语义与 `DoEvents` 等价物（长循环是否会卡住界面）。
5. 一个可用的官方最小工程样例（含 `publish.xml` 原文），用于回归测试。
