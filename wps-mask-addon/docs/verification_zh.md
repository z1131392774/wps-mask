## 已在本地验证通过

```sh
# 在仓库根目录执行
npm install                 # 安装 jsdom，面板与辅助函数测试需要
```

每套也可以单独跑（在仓库根目录），例如 `node wps-mask-addon/test/engine.test.js`；桥的测试文件是 `wps-mask-addon/test/rpc.test.mjs`。

- AES 实现与 node `crypto` 双向逐字节一致（含空串、中文、emoji、5000 字符长文、篡改检测、IV 随机性）。
- 引擎：字段识别、1 对 1 与唯一性、容量与跨度报错、按类型精确还原、整列/整行裁剪、表头开关与 `headerAuto`、备份/读回/回滚、损坏表的明确报错、迁移、设置记忆、混合形态、前导零、后缀位数、整段置换、逐格跳过记录、只还原记录区域的反映射（含二次点击空操作与歧义值）、`prepareMask`/`writeMask`/`abortMask`（保存失败时一格不写并撤回边框；写入失败时单元格、区域与边框记录一起回滚），以及标记边框（混合边不画、只清仍是标记样式的格子、重叠记录只画一块）。
- 面板：卡片与参数、映射与反映射、先保存再写入的流程、保存失败时撤回边框且一格不写、写入失败回滚并重新保存、反映射后保存裁剪过的表、损坏表恢复、表头自动判定提示、清除映射表（含恢复边框的部分失败）、无选区与宿主对象迟到、选区变化重新识别、按列位置记忆设置、区间扩大后沿用同一批假值、只读文档在任何写入前被拒绝。
- 功能区：「快速映射」写值并画上标记边框、记录随映射表落盘；「全部加边框」「全部去边框」重画或去掉边框，不写单元格、不动已映射记录、如实报告部分失败，只读文档在映射、反映射和两个按钮前都被拒绝。
- 桥：一行拆成两段、一个包里多行、CRLF 与空行、噪音行不进配对、`ok:false` 的原因原样传出、超时只影响自己、桥退出时未决调用全部被拒、真子进程一进一出。
- 这里没有任何测试驱动真实的 WPS：全部跑在 `test/mock-wps.js` 和 jsdom 里的面板页面上。

真机上尚未验证：给 `Weight` 赋值是否会把 `LineStyle` 顶成实线（代码把线型放在最后写）、`Border.Color` 读回值是否等于写入的打包整数、混合边宿主是否返回 `null`、单格 `Borders.Item` 与区间语义是否一致，以及 4096 块碎片上限的报错。

## 常见问题

| 现象 | 排查 |
|---|---|
| 功能区没有「数据脱敏」 | 目录名必须是 `wpsmask_1.0.0`；`publish.xml` 的 `version`/`url` 要和目录名一致；改完重启 WPS |
| 面板空白、提示「未取到 WPS 应用对象」 | 任务窗格没拿到宿主对象：对照上节第 2 条 |
| 第一行没有被脱敏 | 它被当成表头了；取消勾选「首行是表头」让第一行当数据，或把选区下移一行 |
| 反映射只还原了一部分 | 只还原记录过的区域，第二次点击是空操作。要用当初映射的选区还原；同一个假值属于两个原值时会被跳过并计入 `有歧义` |
| 保存映射表时弹出失败提示 | 映射表在写单元格之前保存，保存失败时选区一格都没动，重新执行一次映射即可；提示「回滚未完成」时先检查该区域 |
| 提示「映射表损坏，已用备份恢复」 | 主密文损坏，已用备份列恢复；保存一次工作簿把主密文换掉，反复出现就改用备份副本 |
| 重新映射某列却没有变化 | 该列已经是映射结果，被跳过了；要按当前值再映射，先「反映射」 |
| 反映射第二次没有反应 | 第一次反映射已经把记录裁掉了，这是设计上的空操作；再映射一次即可 |
| 表格里残留紫色边框 | 旧失败尝试留下的；功能区的「全部加边框」或「全部去边框」可以清掉。碎片过多的边清到 4096 块会部分停下并如实报错，记录保留，再点一次即可清完；新映射不负责清 |
| 数字列被显示成左对齐文本 | 目标单元格原本是文本格式；改单元格格式即可 |
| 提示「装不下 N 个不同值」 | 区间放不下这么多不同值（如 12 个不同金额却只给 1~5）；自动映射会扩区间，只有手改窄了才会出现 |
| 提示「文档是只读打开的」 | 只读文档上保存会被静默忽略，映射表存不进去；先把文件另存为新文件再脱敏 |
| 提示「写入后读回不一致」 | 某一格写进去没落住；选区里有合并单元格是最常见原因（写非锚点格不报错也不生效），先取消合并再重试；受保护的工作表也会这样 |
| 提示「解密失败」 | `KEY_TEXT` 被改过、隐藏表被手工编辑过，或主密文与备份都损坏；用保存过的文档副本恢复 |
| 混合列里某个值被映射成了「字段名+数字」 | 它不属于那五种形态（中文、单字符、数字开头、`_ . -` 之外的符号）；文本兜底同样一对一、能还原 |
