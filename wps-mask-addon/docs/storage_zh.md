# 映射表的存储位置与加密边界

*[English](storage.md)*

原始值存在哪里、保存失败怎么收场、这层保护做不到什么。使用方式见 [behavior_zh.md](behavior_zh.md)。

- **位置**：本文档的隐藏工作表「脱敏映射表」。A1 是说明文字，A2 起是密文分片（每片 2 万字符，超出自动续行）。B 列是备份区：B1 是备份标记，B2 起保存上一份密文。每次保存前会丢掉已没有任何区域记录引用的旧签名桶，反复放宽区间不会让这张表无限变大。
- **算法**：AES-128-CBC + 随机 IV + PKCS#7，Base64 后加 `M1:` 前缀。同一明文两次保存的密文不同。没有 MAC：只有解密或 JSON 结构校验失败时才会发现被改动，无法证明密文一定未被篡改。
- **密钥**：`js/aes.js` 顶部 `KEY_TEXT`（16 字节）。
- **保存前先校验**：保存时先把上一份密文复制到备份列并读回校验，再把新密文写入 A 列，读回并解密比对。任何一步失败都会回滚：`已回滚到上一份映射表`、`已清空本次未完成写入`，或保留备份（`回滚未完成…备份区保留上一份密文，重新读取时会自动恢复`）。面板和快捷按钮都是先保存映射表、再写单元格，所以保存失败时一格都不动。
- **读取损坏的表要出声**：没有隐藏表 = 新建文档、空映射。本文档一旦由这个加载项写过映射表，主密文为空或读不出时就不会被当成新文档：主密文为空是错误（`映射表密文为空，为保护数据不返回空映射表…`），要重建就用「删除映射表」。主密文损坏而备份可读时，自动用备份恢复并提示 `映射表损坏，已用备份恢复，请重新保存`；两份都不可用时直接报解密/内容错误，不会假装「本文档没有映射」。
- **保护边界**：密钥写在代码里，因此这只是一种混淆手段：能防止直接打开文档查看原值，但无法防止持有这份加载项的人反向解密。如果需要让外部人员无法解密，必须把密钥移出文档，改为从本机配置或口令派生。
- **谁能还原**：任何持有这一版加载项的人，不需要口令——点一次「反映射」就会查表写回原值。卸载加载项、换一台机器、把文档转给别人、或在禁用加载项的环境里打开，界面上就没有还原入口；只凭文档本身也还原不出来。
- **WPS 可能另留副本**：备份中心、云端历史版本、撤销栈里可能仍有脱敏前的原值。脱敏这份工作簿不等于删掉那些副本。
- **公式会被覆盖**：公式单元格写入的是常量假值，公式就此丢失；反映射还原的是数值，不是公式。工作表还要继续算公式时，先留备份。
- **隐藏表不是保险柜**：会写宏的人可以取消隐藏、读取密文；删掉这张表——或另存一份不带它的副本——映射就彻底丢失，加载项也无法还原。加载项只按名字认表：你自己建一张叫「脱敏映射表」的工作表，会被当成映射表处理。旧格式文档升级时如果搬桶被迫丢过记录，升级前写下的区域没有签名可查，加载项会把它们留空并计入歧义，而不是猜一个原值写回去。
- **只记最近 200 个区域**：保险箱保留最近 200 个「已映射」矩形，超出后丢最旧的。映射过的区域超过 200 个之后，最旧的那些在界面上就无法反映射了——它们的假值会一直留着，除非用文档的备份副本恢复。
- **标记边框的原样式也在密文里**：`marks` 记的是每个已映射块四条边加边框前的线型、粗细、颜色，不含任何单元格内容，体积相对映射本身可以忽略。区域与边框记录在写单元格之前的那一次保存里一起落盘；保存失败会用 `abortMask` 把已画的边框撤回，写入失败则把单元格、区域记录和边框记录一起回滚。清除映射表时先用它把边框恢复掉、再删隐藏表；恢复失败会逐表如实报错。
- **前置检查只有一项**：只读文档在保存映射表之前就会被拒绝——真机上只读的 `Save()` 既不抛错也不写盘，映射表会「保存成功」地丢掉，脱敏之后再也还原不回来。受保护与合并单元格不预检，靠写入后的读回校验兜住：宿主拒绝或静默丢弃都会让整批回滚并报错。
- **假值还能看出什么**：数字列在区间内随机取值，区间按数据范围外再留 10% 余量（如 20~43），所以假值不是原列的重排——排序后的多重集、频次分布都与原列不同。但区间的最小/最大值、行数、空值位置、行顺序仍然可见，文本与手机号列的位数、形态也照旧保留。
- **修改密钥的代价**：修改后，旧文档中的映射表全部无法解密（面板提示「解密失败」）。已有文档包含映射表时不要修改。
- **务必保存文档**：映射表随文档一起保存。映射后不保存就关闭窗口，脱敏数据仍在，但映射表丢失，数据将无法还原。
