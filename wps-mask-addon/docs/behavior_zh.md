# 脱敏行为

*[English](behavior.md)*

加载项如何决定脱敏方式、写入什么、反映射还原什么。安装与功能对照见 [README_zh.md](../README_zh.md)，加密表见 [storage_zh.md](storage_zh.md)。

## 识别顺序

引擎把选区当作一整块读取，每列的映射方式按值的 JS 类型判定：

1. 非空值全是数字 → 数字。
2. 非空值全是文本（含纯数字字符串）→ 文本，前缀取字段名。
3. 数字和文本混排 → 混合：数字换数字，文本换非数字文本。

类型看的是值的 JS 类型，不看形态：手机号、邮箱、带前导零的账号只要存成文本，就按文本处理。这样写入时不会被 WPS 当成数字转掉前导零。

整列选区会裁剪成「第 1 行到该列最后一个非空单元格」（`End(xlUp)`），整行选区裁剪到「最后一个用到的列」（`End(xlToLeft)`）；整列全空的列直接跳过。

## 表头行

第一行算不算表头，由面板的「首行是表头」复选框决定：勾了就按表头处理；不勾时由自动识别猜：这一行基本是文本，且命中已知字段词、或下一行出现数字、或选区从工作表第 1 行开始。**自动识别会猜错。** 第一条数据里恰好有「备注」这类字眼时，它会被当成表头整行不脱敏——表面看数据已经处理过，原样的第一行却还在。点「映射并写入」之前，先看面板上标的是「首行为字段名」还是「无表头」；要把第一行当数据，就取消勾选。

判得没把握时（这一行被自动判成表头、每列都只能按文本处理、而用户还没动过复选框），面板会在选区信息后面追加一句：`；首行自动判定为字段名，若首行其实是数据，请取消勾选「首行是表头」`。勾选或取消勾选一次就算用户已经确认，提示不再出现；「重新识别」回到自动判断，提示可能重新出现。

## 映射与反映射

**面板方式。** 选中要处理的区域（整列 / 整行 / 任意块都行），打开「映射面板」：面板自动读取选区，选区变化时自动更新，不需要手动刷新。每列一张卡片，自动判断成数字/文本/混合，示例值显示在卡片头部，参数在下方按需展开。改过的卡片参数在选区刷新后按「工作表 + 列位置」保留。「映射并写入」直接写回原区域；「反映射回原值」只还原选区里这个加载项映射过的区域，它没写过的格子保持原样。

**重复映射不会叠加。** 只有落在映射写过的区域内、且值能通过映射表反查的单元格才会被跳过，状态栏会显示跳过的格数。所以「先映射两列、再选全区映射」不会把那两列映射第二次；反映射时这些记录会扣掉已还原的部分，所以第二次反映射没有东西可写。要基于当前值再映射一遍，先「反映射」。

**表格里的标记边框。** 映射写完后，这块区域的外圈会套一圈紫色虚线边框：不开面板也能一眼看出哪里已经脱敏，区域内部的网格线不动。边框跟着区域记录走——反映射裁掉一块，边框跟着消失；整块还原完，边框回到原来的样式。功能区的「全部加边框」「全部去边框」可以一键重画或去掉所有块的边框，只改外观，不改「已映射」状态，也不动单元格的值。它们也会清掉旧失败尝试留下的紫线；新的映射不负责清：没写入任何格子的映射不碰任何边框。

这些矩形在映射的那一刻就写进文档的隐藏表，反映射和边框都靠它找到位置；关掉文档之后要保留，才需要保存文档。

加边框前，每条边原来的线型、粗细、颜色会记进映射表（和映射一起，在那唯一一次保存里、写单元格之前落盘），「去边框」时按记录写回去，用户自己的表格边框不会被吃掉。一条边在整块里样式不一致时，宿主读不出唯一样式，这种边记为空：不画；清除时也只清仍是紫色标记的格子，不整条清。工作表被保护等原因画不上边框时，数据照常写入，状态栏追加一句 `；区域边框没画上：…`，不假装成功。写入了单元格的映射只重画本次新区域，以及与它重叠或合并成一块的旧区域；无关区域的边框不动。要重刷所有已记录区域，用「全部加边框」。

**快捷方式**（不打开面板，用自动识别或上次记住的设置）

- 「快速映射」：直接处理当前选区。已映射的格子一样跳过；没有新数据时只提示、不写入。成功只在底部状态栏报一句格数，一直保留到下一次提示，并追加本次耗时，不弹窗；失败才弹窗。
- 「反映射」：只还原选区里记录过的区域，没映射过的格子不动；没有可还原的内容时提示一句，不写任何单元格。

**提示消息。** 快捷操作成功时状态栏显示 `已映射 12 格`（有格子已映射过时是 `，跳过 3 格`）或 `已还原 12 格`（`，2 格没有映射记录`；同一个假值属于两个原值时追加 `，1 格有歧义未还原`）。失败改为弹窗：没有新数据可映射时 `这个区域已经映射过，先执行「反映射」再映射。`；选区里没有记录过的区域时 `没有可还原的映射，选区要和映射时一致。`；映射表保存失败时 `映射表保存失败：…，没有写入任何单元格，已撤回区域边框，请重新映射。`；写入被宿主拒绝时 `写入失败：…；已回滚，请重新映射。`（回滚没做干净时是 `回滚未完成，请检查表格后重新映射。`）；回滚后保存也失败时 `写入失败：…；回滚后的映射表没保存：…，请检查映射表。`；反映射后映射表保存失败时 `映射表未保存：…，请勿关闭文档，重新映射前先检查映射表。` 反映射后边框没更新时追加 `；区域边框没更新：…`；加/去边框按钮分别回 `已给 N 块区域加上边框` / `已去掉 N 块区域的边框`，没有可操作区域时也会说明。面板在状态行报告同样的结果。功能区成功提示末尾追加 `。耗时 N 毫秒/秒。`，并一直保留到下一次提示。

**通用约定**

- 空白单元格不动。
- 「不处理」列完全跳过。
- 数值单元格读回的是序列号（日期也是数字），映射后仍是数字、格式不变；反映射按原类型写回。
- 文本原值写回时带宿主的文本标记（前导单引号），`008081` 这类值仍是文本，单元格格式不变。
- 数字映射保留原列的小数位；整数列生成整数。

## 混合列

混合列里可能同时有数字和文本。设为「混合」后按值的 JS 类型处理：数字换成数字列区间内的值；文本换成「字段名 + 数字」，并保证含非数字字符，宿主不会把它转成数字。手机号、邮箱、固话、带前导零的编码只要存成文本，都按普通文本处理，不再保持原形态。一对一映射仍然成立：原值是唯一的键，反映射与新值的类型无关。
