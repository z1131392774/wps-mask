# 引擎实现细节

*[English](implementation.md)*

[AGENTS_zh.md](../AGENTS_zh.md) 里各条规则背后的约定。改生成、分类或映射表格式之前先读这里；规则文件只留一行规则，理由和坑在这里。

## 一对一映射

映射表按 `n:` / `s:` / `b:`（数字、字符串、布尔）键入。生成器用 `used[原值]` 探测撞不上任何东西，因为表的键不是原值：`genPhone` / `genText` 曾经这么写，十六次里有一次反映射回了别人的原值。要探测 `used[keyOf(候选假值)]`。

数值区间刚好只放得下这些不同值时，把整列随机置换（`sattolo()`，一个环、无不动点）。逐个生成会把最后一个逼回它自己的值并随机失败；固定偏移等于把原列整体旋转，谁都能反推。区间放不下就报错，并报出列字母与表头。

`assignExact` 先算跨度再物化：上限 1,000,000 个值，`min`/`max` 非有限数直接拒绝，而不是拿去循环。跨度太大无法置换时退回普通随机分配。

## 混合列形态

`shapeOf()` 返回 mobile / email / landline / digits / alnum / text；`genMixed` 分派到保持该形态的生成器，否则用 `genText`。新增形态需要三样：`shapeOf` 分支、生成器、以及一条断言什么必须保住的测试——域名、区号、位数、前导零。反映射仍以原值为键，生成过假值的形态在还原时无关紧要。

## 映射表格式

`M1:`、`sigOf()` 和 `KEY_TEXT` 会被已存在的文档读取；改一个，旧桶就匹配不上。要么同一改动里加版本字段和迁移，要么在记录里说明为什么留成孤儿无妨。`sigOf()` 里每个字段都必须改变输出；只改签名不改输出的字段会悄悄把所有人改名，`lang` 就这样同时把值空间也拆了。

记住的 `min`/`max` 是数据不是策略：与当前批数据取并集、只增不减，再 `absorbBucket()`。区域仍引用的桶要保留；记录的签名找不到桶时绝不回退到全局索引，那些格子计入歧义。只因为区域引用而保留的桶，在下次保存 `pruneUnusedBuckets()` 时若已无引用就删除。

保存分两段：上一份密文先备份到 B 列并读回，新密文写入 A 列后读回、解密比对；失败则回滚或保留备份。`checkWritten()` 会重读这批写入（按宽松类型容忍宿主格式化），宿主静默吞掉写入时整批失败，而不是报告成功。

## 面板与功能区渲染

面板里禁止 flex `gap`、CSS 变量和 grid：浏览器版本未知，这些会静默失效。面板只显示类型、一个示例和参数；计数归状态栏，每种状态一句话。功能区图标是 `assets/icons/` 里的 SVG，由 `tools/make-icons.mjs` 生成 PNG；只有 `getImage` 回调能显示，按钮的 `image=` 会被忽略。用 `node tools/preview-pane.mjs` 在 260、300、380 px 截图。
