# Mapping storage and encryption limits

*[中文](storage_zh.md)*

Where the originals live, how a save survives a failure, and what the protection cannot do. Usage is in [behavior.md](behavior.md).

- **Location:** a hidden worksheet named "脱敏映射表". A1 is a notice, A2 onward holds ciphertext chunks of 20,000 characters. Column B is the backup area: B1 marks it, B2 onward keeps the previous ciphertext. Each save drops signature buckets no recorded area references any more, so widening an interval repeatedly does not grow the table without bound.
- **Algorithm:** AES-128-CBC, random IV, PKCS#7, Base64 behind an `M1:` prefix. Two saves of one plaintext differ. No MAC, so damage is reported only when decryption or the JSON check fails.
- **Key:** `KEY_TEXT` at the top of `js/aes.js`, 16 bytes.
- **A save is verified before any cell is written.** The previous ciphertext is copied to the backup column and read back, then the new ciphertext is written to column A and read back to compare. A failure rolls back to the previous table (`已回滚到上一份映射表`), clears a half-written save (`已清空本次未完成写入`), or keeps the backup (`回滚未完成…备份区保留上一份密文，重新读取时会自动恢复`). The panel and quick buttons save before writing cells, so a failed save writes nothing.
- **Loading a damaged table is loud.** No hidden table means a new document and an empty mapping. Once the add-in has written a table, an empty or unreadable main copy is not a new document: an empty copy is an error (`映射表密文为空，为保护数据不返回空映射表…`) — delete the table to start over. If the main ciphertext is damaged but the backup is readable, it recovers from the backup and says `映射表损坏，已用备份恢复，请重新保存`; when neither copy is usable it reports the error instead of pretending there is no mapping.
- **Protection limit:** the key ships with the code, so this is obfuscation only. It prevents reading the originals by simply opening the workbook; it cannot stop someone holding this add-in from decrypting the table. Real protection requires deriving the key from a local config or a passphrase, outside the document.
- **Who can restore:** anyone holding this add-in version can click "反映射" — no passphrase — and get the originals back. Uninstalling the add-in, switching to another machine, forwarding the workbook to someone without it, or opening it where add-ins are blocked leaves no UI path to the originals; the document alone cannot produce them.
- **WPS may keep copies elsewhere:** the backup center, cloud version history, and the undo stack can still hold pre-masking values. Masking the workbook does not delete those copies.
- **Formulas are overwritten:** a formula cell receives a constant fake, and the formula is gone. Reverting restores the value, not the formula; keep a copy when the sheet is a working model.
- **The hidden sheet is not a lock:** anyone with a macro can unhide it or read its ciphertext, and deleting it — or saving a copy without it — loses the mapping for good. It finds the table by name alone: a sheet you named 脱敏映射表 is treated as the mapping table; it cannot restore data whose table is gone. Old-format (v1) documents: if upgrading dropped records while merging buckets, areas recorded before signatures existed are left untouched and counted ambiguous instead of guessing an original.
- **Only the last 200 masked areas are remembered:** the vault keeps the 200 most recent masked rectangles and drops the oldest. Once more than 200 areas have been masked, revert can no longer restore the oldest of them from the UI; their fakes stay unless a saved copy of the document is restored.
- **The pre-mark border styles live in the ciphertext too:** `marks` stores the line style, weight and colour each edge of a masked block had before the outline was painted — no cell contents, and negligible size next to the mapping. Areas and marks are written in the same single save that happens before any cell is written; a failed save takes the painted outlines back (`abortMask`), and a failed write rolls the cells back and keeps records only for the columns it could not restore, each with a per-row snapshot of the planned fakes, so revert checks those cells one by one instead of looking a value up in a bucket, the snapshot is consumed as revert writes, and older documents load unchanged; the outline records stay. Clearing the table restores the outlines before the hidden sheet is deleted, and a restore failure is reported per sheet.
- **One pre-flight check only:** a read-only document is refused before the table is saved: on a real host `Save()` opens a modal 「replace this file?」 prompt — Cancel throws an HRESULT, Yes returns without writing, and the prompt blocks an unattended COM run. Protected and merged cells are not pre-checked; the read-back catches both, so a refusal or a silent drop rolls the batch back with an error.
- **What the fakes still reveal:** fakes are drawn at random from a range with 10% headroom past the data (20~43, not 20~40): the column is not reshuffled, neither sorted values nor frequencies match. Still visible: the range's min and max, row count, blanks, row order, and the text-fake field-name prefix.
- **Cost of changing the key:** every existing document's table becomes undecryptable (the panel reports a decryption failure); do not change it while such documents exist.
- **Save to keep the result.** The table and masked values live in the same workbook; closing without saving discards both and leaves the file original. Masked values outlive the table only when it is deleted or a copy is saved without it.
