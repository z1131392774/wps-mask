# 数据脱敏映射 · WPS 表格加载项

*[English](README.md)*

选中一块区域，把里面的数据按规则替换成看似真实的假数据；原始值加密保存在文档中，随时可以一键还原。

---

## 一、需求对照

| 需求 | 实现方式 |
|---|---|
| 选区域 → 数据映射成随机数据 | 功能区「数据脱敏 → 映射面板」，或免界面的「快速映射」 |
| 1.1 一对一，同值同结果 | 映射表按 `原值 → 新值` 持久化；同一原值始终取同一条记录，不同原值分配到不同新值。碰撞时重试；容量不足时报错，不产生重复值 |
| 1.2 数字 / 文本两种映射值 | 「映射为」下拉：手机号、数字、文本、混合、不处理 |
| 1.2.1 数字可设参数，默认均匀 | 均匀分布（默认）、正态分布（均值/标准差，越界值折回区间）、指数分布（λ 控制衰减）；范围、小数位可改 |
| 1.2.2 手机号必须合法 | 11 位：真实 3 位号段（如 138、150、186）+ 8 位随机数字，保证 `1[3-9]` 开头，列内不重复、不与原值相同 |
| 1.2.3 文本 = 前缀 + 随机数字后缀 | 前缀默认取字段名（如「姓名37」），可改。后缀位数默认取能容纳本列非空单元格数的最小位数，另留 10% 余量：41 行客户名对应 2 位后缀（姓名37），不会写成「姓名0037」；可手动改为 1–8 位 |
| 1.3 自动识别字段名与类型 | 字段名关键词、邮箱/固话形态、手机号或数值占比、文本兜底，按固定优先级判定，顺序见下方「识别顺序」。整列、整行选区先裁剪到实际有数据的范围再判定 |
| 2 一键反映射，映射关系加密 | 「反映射回原值」按加密表反查写回（保留数字/文本类型与空值）。只还原这个加载项记录过「已映射」的区域：扩大选区不会误改没脱敏的列，连点第二次是空操作；同一个假值可能属于两个原值时，它不猜，留给用户并计数。映射表为 AES-128-CBC 密文，存放于隐藏工作表 |
| 3 记住本文档上次的设置 | 每列的类型/分布/参数/前缀按字段名记在同一个加密块里，下次选中同一字段自动套用；数值区间只扩不缩（取上次区间与本批数据范围的并集），别的 sheet 同名列值域更宽也不会被旧区间卡住；「重新识别」忽略已记设置，重新检测 |

### 识别顺序

引擎把选区当作一整块读取，每列的映射方式按以下顺序判定：

1. 只要出现邮箱或固话值 → 混合。
2. 字段名命中且至少一半的值形如手机号 → 手机号。
3. 字段名没命中，但 ≥60% 的值形如手机号 → 手机号。
4. 字段名命中，值是什么都行 → 手机号。
5. ≥80% 的值是数值 → 数字。
6. 手机号 / 纯数字 / 字母数字 / 文本这四族里至少出现两族 → 混合。
7. 其余 → 文本，前缀取字段名。

整列选区会裁剪成「第 1 行到该列最后一个非空单元格」（`End(xlUp)`），整行选区裁剪到「最后一个用到的列」（`End(xlToLeft)`）；整列全空的列直接跳过。

第一行是不是表头，只取决于面板的「首行是表头」复选框；不勾时由自动识别猜：这一行基本是文本，且命中已知字段词、或下一行出现数字、或选区从工作表第 1 行开始。**自动识别会猜错。** 第一条数据里恰好有「备注」这类字眼时，它会被当成表头整行不脱敏——表面看数据已经处理过，原样的第一行却还在。点「映射并写入」之前，先看面板上标的是「首行为字段名」还是「无表头」；要把第一行当数据，就取消勾选。

判得没把握时（这一行被自动判成表头、每列都只能按文本处理、而用户还没动过复选框），面板会在选区信息后面追加一句：`；首行自动判定为字段名，若首行其实是数据，请取消勾选「首行是表头」`。勾选或取消勾选一次就算用户已经确认，提示不再出现；「重新识别」回到自动判断，提示可能重新出现。

## 二、安装（不需要 node 和 wpsjs，直接复制文件）

加载项目录在 `%APPDATA%\kingsoft\wps\jsaddons`（`Win+R` 输入 `%appdata%` → `kingsoft\wps\jsaddons`，没有就新建）。

不需要 Node.js、npm 或 `wpsjs`：加载项就是纯文件，下面三步就是全部安装过程。

1. 把 `wpsmask_1.0.0` 整个文件夹复制进去。**目录名不要改**，`名字_版本号` 是 WPS 识别加载项的依据。
2. 处理清单文件 `publish.xml`：
   - 目录里没有 → 把本仓库 `wps-mask-addon/publish.xml` 复制进去；
   - 已经有（装过别的加载项）→ **不要覆盖**，只把这一行加进 `<jsplugins>` 里：

   ```xml
   <jsplugin name="wpsmask" type="et" url="wpsmask_1.0.0" version="1.0.0" enable="enable" install="null" customDomain="" debug=""/>
   ```
3. 重启 WPS，打开任意表格，功能区出现「数据脱敏」选项卡。首次加载时 WPS 可能弹出信任提示，允许即可。

最终目录结构：

```
jsaddons\
├─ publish.xml
└─ wpsmask_1.0.0\
   ├─ index.html        入口页（WPS 启动时加载）
   ├─ main.js           串联脚本
   ├─ ribbon.xml        功能区定义
   ├─ images\           功能区图标：panel / quick / revert，各带一份 @2x
   ├─ js\
   │   ├─ utils.js      取应用对象、算资源路径
   │   ├─ aes.js        AES-128-CBC（纯 JS）
   │   ├─ engine.js     识别 / 生成 / 映射表 / 加解密落盘
   │   └─ ribbon.js     按钮回调、快捷映射与反映射
   └─ taskpane\
       ├─ index.html    映射面板
       ├─ taskpane.css
       └─ taskpane.js
```

仓库 `assets/icons/` 里的 SVG 源文件不复制，只复制生成好的 PNG。

> 如果已安装 `wpsjs`（不是必需），可以使用它生成的 `publish.xml`，按同名替换上述文件；`wpsjs debug` 可以直接加载加载项并启动 WPS。

### 开发时免去复制

仓库里的改动只有复制到 `jsaddons` 后才会生效。`tools/link-addon.ps1` 把复制过去的文件夹替换为指向工作区的目录联接（junction），WPS 直接读取工作区文件，改完后只需重启 WPS：

```powershell
powershell -File tools/link-addon.ps1            # 建立联接；原文件夹保留为 .bak-<时间戳>
powershell -File tools/link-addon.ps1 -Rollback  # 删除联接，恢复备份
```

目录联接不需要管理员权限或开发者模式，普通文件接口也能正常访问；硬链接只能指向文件，不能指向文件夹。操作前先关闭 WPS，否则加载项占用会导致改名失败。

## 三、使用

**面板方式**
1. 选中要处理的区域（整列 / 整行 / 任意块都行）。
2. 打开「映射面板」：面板自动读取选区，选区变化时自动更新，不需要手动刷新；未选中区域时只显示一行提示，工具栏不显示，写入按钮置灰。
3. 每列一张卡片，自动判断成手机号/数字/文本：示例值显示在卡片头部，参数在下方按需展开。逐列核对「映射方式」和参数。改过的卡片参数在选区刷新后按「工作表 + 列位置」保留。
4. 「映射并写入」→ 直接写回原区域。再点「反映射回原值」时，只还原选区里这个加载项映射过的区域，它没写过的格子保持原样。

**表头行。** 「首行是表头」复选框决定第一行算不算数据：勾选时第一行永远不参与脱敏，并作为列名和文本前缀的来源；不勾时第一行是数据，自动识别仍可能把它猜成表头（见「识别顺序」，那里也说明了判得没把握时面板给出的提示）。面板上会标出「首行为字段名」或「无表头」，写入前先确认。

**重复映射不会叠加。** 只有落在映射写过的区域内、且值能通过映射表反查的单元格才会被跳过，状态栏会显示跳过的格数。所以"先映射两列、再选全区映射"不会把那两列映射第二次；反映射时这些记录会扣掉已还原的部分，所以第二次反映射没有东西可写。要基于当前值再映射一遍，先「反映射」。

**快捷方式**（不打开面板，用自动识别或上次记住的设置）
- 「快速映射」：直接处理当前选区。已映射的格子一样跳过；没有新数据时只提示、不写入。成功只在底部状态栏报一句格数，几秒后消失，不弹窗；失败才弹窗。
- 「反映射」：只还原选区里记录过的区域，没映射过的格子不动；没有可还原的内容时提示一句，不写任何单元格。

**提示消息。** 快捷操作成功时状态栏显示 `已映射 12 格`（有格子已映射过时是 `，跳过 3 格`）或 `已还原 12 格`（`，2 格没有映射记录`；同一个假值属于两个原值时追加 `，1 格有歧义未还原`）。失败改为弹窗：没有新数据可映射时 `这个区域已经映射过，先执行「反映射」再映射。`；选区里没有记录过的区域时 `没有可还原的映射，选区要和映射时一致。`；映射表保存失败时 `映射表保存失败：…，没有写入任何单元格，请重新映射。`；写入被宿主拒绝时 `写入失败：…；已回滚，请重新映射。`（回滚没做干净时是 `回滚未完成，请检查表格后重新映射。`）；反映射后映射表保存失败时 `映射表未保存：…，请勿关闭文档，重新映射前先检查映射表。` 面板在状态行报告同样的结果，映射成功后追加 `，记得保存文档。`。

**通用约定**
- 空白单元格不动。
- 「不处理」列完全跳过。
- 数值单元格读回的是序列号（日期也是数字），映射后仍是数字、格式不变；反映射按原类型写回。
- 数字映射保留原列的小数位；整数列生成整数。

**混合列（手机、邮箱、固话、工号混在同一列）**
账号列经常同时包含多种格式。把这一列设为「混合」后，每个单元格按自身形态分别处理：

| 原值形态 | 映射成 |
|---|---|
| 手机号 | 另一个合法手机号 |
| 邮箱 | `u` + 6 位数字，**域名保留**（`li.na@corp.com` → `u005288@corp.com`）|
| 固话 | 区号、分隔符、位数、分机号都保留（`020-88997766` → `020-41283071`）|
| 纯数字 | 同位数数字，前导零保留（`000123` → `000233`）|
| 字母数字账号 | 逐字替换同形态（`kf_2024_001` → `ud_9309_739`）|
| 其余（中文等）| 回落到「字段名 + 数字」 |

一对一映射仍然成立：原值是唯一的键，反映射与新值的生成形态无关。注意两点：邮箱域名会保留（`@corp.com` 依然可见）；过短的账号（如 `a1`）可用的同形态组合有限，用尽时会报错，不会生成重复值。

## 四、映射表的存储位置与加密边界

- **位置**：本文档的隐藏工作表「脱敏映射表」。A1 是说明文字，A2 起是密文分片（每片 2 万字符，超出自动续行）。B 列是备份区：B1 是备份标记，B2 起保存上一份密文。每次保存前会丢掉已没有任何区域记录引用的旧签名桶，反复放宽区间不会让这张表无限变大。
- **算法**：AES-128-CBC + 随机 IV + PKCS#7，Base64 后加 `M1:` 前缀。同一明文两次保存的密文不同。没有 MAC：只有解密或 JSON 结构校验失败时才会发现被改动，无法证明密文一定未被篡改。
- **密钥**：`js/aes.js` 顶部 `KEY_TEXT`（16 字节）。
- **保存前先校验**：保存时先把上一份密文复制到备份列并读回校验，再把新密文写入 A 列，读回并解密比对。任何一步失败都会回滚：`已回滚到上一份映射表`、`已清空本次未完成写入`，或保留备份（`回滚未完成…备份区保留上一份密文，重新读取时会自动恢复`）。面板和快捷按钮都是先保存映射表、再写单元格，所以保存失败时一格都不动。
- **读取损坏的表要出声**：没有隐藏表 = 新建文档、空映射。本文档一旦由这个加载项写过映射表，主密文为空或读不出时就不会被当成新文档：主密文为空是错误（`映射表密文为空，为保护数据不返回空映射表…`），要重建就用「删除映射表」。主密文损坏而备份可读时，自动用备份恢复并提示 `映射表损坏，已用备份恢复，请重新保存`；两份都不可用时直接报解密/内容错误，不会假装"本文档没有映射"。
- **保护边界**：密钥写在代码里，因此这只是一种混淆手段：能防止直接打开文档查看原值，但无法防止持有这份加载项的人反向解密。如果需要让外部人员无法解密，必须把密钥移出文档，改为从本机配置或口令派生。
- **谁能还原**：任何持有这一版加载项的人，不需要口令——点一次「反映射」就会查表写回原值。卸载加载项、换一台机器、把文档转给别人、或在禁用加载项的环境里打开，界面上就没有还原入口；只凭文档本身也还原不出来。
- **WPS 可能另留副本**：备份中心、云端历史版本、撤销栈里可能仍有脱敏前的原值。脱敏这份工作簿不等于删掉那些副本。
- **公式会被覆盖**：公式单元格写入的是常量假值，公式就此丢失；反映射还原的是数值，不是公式。工作表还要继续算公式时，先留备份。
- **隐藏表不是保险柜**：会写宏的人可以取消隐藏、读取密文；删掉这张表——或另存一份不带它的副本——映射就彻底丢失，加载项也无法还原。加载项只按名字认表：你自己建一张叫「脱敏映射表」的工作表，会被当成映射表处理。旧格式文档升级时如果搬桶被迫丢过记录，升级前写下的区域没有签名可查，加载项会把它们留空并计入歧义，而不是猜一个原值写回去。
- **只记最近 200 个区域**：保险箱保留最近 200 个"已映射"矩形，超出后丢最旧的。映射过的区域超过 200 个之后，最旧的那些在界面上就无法反映射了——它们的假值会一直留着，除非用文档的备份副本恢复。
- **没有前置检查**：只读、受保护、合并单元格在写入前不会检查。写入被拒绝时会回滚已写的列并报错；如果回滚本身也失败，提示会说明，单元格可能停在部分脱敏的状态。
- **假值还能看出什么**：数字列在区间内随机取值，区间按数据范围外再留 10% 余量（如 20~43），所以假值不是原列的重排——排序后的多重集、频次分布都与原列不同。但区间的最小/最大值、行数、空值位置、行顺序仍然可见，文本与手机号列的位数、形态也照旧保留。
- **修改密钥的代价**：修改后，旧文档中的映射表全部无法解密（面板提示"解密失败"）。已有文档包含映射表时不要修改。
- **务必保存文档**：映射表随文档一起保存。映射后不保存就关闭窗口，脱敏数据仍在，但映射表丢失，数据将无法还原。

**尚未在真机验证的条目**（本地文档没有这些接口的实测资料，实现依据官方和社区样例）：

1. `publish.xml` 的字段与 `enable` 取值是否被当前 WPS 版本接受 → 判断标准：功能区出现「数据脱敏」。
2. **任务窗格网页里 `window.Application` 是否注入**。这是最关键的一项：如果面板显示"未取到 WPS 应用对象"，说明该版本的任务窗格无法获取宿主对象，需要改为由宿主页执行（`ribbon.js` 中已有相同的引擎调用，可暂时使用「快速映射/反映射」完成操作）。
3. `CreateTaskPane` 是否接受 `file://` 形式的相对路径 URL。
4. `Worksheets.Add(undefined, 末表)` 是否返回工作表对象。代码只调用这一次，没有退路；宿主拒绝时隐藏映射表建不出来，脱敏会直接报错停下。
5. 隐藏工作表（`Visible = 2`）保存为 `.xlsx`/`.et` 后重开能否正常读回密文。
6. 大数据量（十万行级）的性能与界面卡顿。
7. 只读、受保护、合并单元格是否像"先保存再写入 + 失败回滚"假设的那样表现。

**把这七条变成结论**：`tools/live/probe.mjs` 逐条去问真实宿主，一行为一个结论。

## 六、常见问题

| 现象 | 排查 |
|---|---|
| 功能区没有「数据脱敏」 | 目录名必须是 `wpsmask_1.0.0`；`publish.xml` 的 `version`/`url` 要和目录名一致；改完必须重启 WPS |
| 面板空白、提示"未取到 WPS 应用对象" | 见上节第 2 条 |
| 第一行没有被脱敏 | 它被当成表头了：要么勾了「首行是表头」，要么自动识别猜成了表头。取消勾选让第一行当数据处理，或把选区下移一行 |
| 反映射只还原了一部分 | 只还原映射表记录过的区域，且第二次点击是空操作。要用当初映射的选区来还原；每个记录区域保留映射当时的签名，之后再改该列参数不影响还原；同一个假值属于两个原值时会被跳过并计入 `有歧义` |
| 保存映射表时弹出失败提示 | 映射表在写单元格之前保存，保存失败时选区一格都没动，重新执行一次映射即可；提示里说"回滚未完成"时，先检查该区域再重试 |
| 提示"映射表损坏，已用备份恢复" | 主密文损坏，已用备份列恢复。保存一次工作簿把主密文换掉；反复出现就改用备份副本 |
| 重新映射某列却没有变化 | 该列已经是映射结果，被跳过了。要按当前值再映射一遍，先「反映射」 |
| 反映射第二次没有反应 | 第一次反映射已经把记录裁掉了，这是设计上的空操作；要重新获得记录，再映射一次 |
| 数字列被显示成左对齐文本 | 目标单元格原本是文本格式，映射写入的数值保留了该格式，改单元格格式即可 |
| 提示"装不下 N 个不同值" | 整数区间里放不下这么多不同值（如 12 个不同金额却只给 1~5）。自动映射会按数据范围扩区间，正常不会出现；只有你手改窄了区间才会，放宽范围或改小数位 |
| 提示"解密失败" | `KEY_TEXT` 被改过、隐藏表被手工编辑过，或主密文与备份都损坏；用保存过的文档副本恢复 |
| 混合列里某个值被映射成了「字段名+数字」 | 它不属于那五种形态（中文、只有一个字符、`2024abc` 这类数字开头的编码、或带 `_ . -` 和空格之外的符号），因此使用文本兜底——兜底同样一对一，也能还原 |
