# 数据脱敏映射 · WPS 表格加载项

*[English](README.md)*

选中一块区域，把里面的数据按规则替换成"看起来像真的"的假数据；原始值加密存进文档，随时一键还原。

---

## 一、需求对照

| 你提的要求 | 这里的实现 |
|---|---|
| 选区域 → 数据映射成随机数据 | 功能区「数据脱敏 → 映射面板」，或免界面的「快速映射」 |
| 1.1 一对一，同值同结果 | 映射表按 `原值 → 新值` 持久化；同一原值永远取同一条记录，不同原值强制分配到不同新值（撞车重试，容量不足直接报错而不是悄悄重复） |
| 1.2 数字 / 文本两种映射值 | 「映射为」下拉：手机号、数字、文本、不处理 |
| 1.2.1 数字可设参数，默认均匀 | 均匀分布（默认）、正态分布（均值/标准差，越界折回区间）、指数分布（λ 控制平缓度）；范围、小数位可改 |
| 1.2.2 手机号必须合法 | 从真实号段（130–199）取 3 位前缀 + 8 位随机，保证 `1[3-9]` 开头共 11 位，列内不重复、不与原值相同 |
| 1.2.3 文本 = 前缀 + 随机数字后缀 | 中文前缀（默认取字段名，如「姓名9527」）或英文前缀（内置 姓名→Name、地址→Address 等词表，也可自填），后缀位数 1–8 可调 |
| 1.3 自动识别字段名与类型 | ①字段名命中 手机/电话/phone/tel 等 → 手机号；②≥60% 数据形如手机号 → 手机号；③≥80% 是数值 → 数字；④其余 → 文本（前缀取字段名）。整列、整行选中都能正确取字段名 |
| 2 一键反映射，映射关系加密 | 「反映射回原值」按加密表反查写回（保留数字/文本类型与空值）；映射表为 AES-128-CBC 密文，存放于隐藏工作表 |
| 3 记住本文档上次的设置 | 每列的类型/分布/参数/前缀按字段名记在同一个加密块里，下次选中同一字段自动套用；「重新识别」可忽略记忆重来 |

## 二、安装（免 node、免 wpsjs，纯文本放置）

加载项目录在 `%APPDATA%\kingsoft\wps\jsaddons`（`Win+R` 输入 `%appdata%` → `kingsoft\wps\jsaddons`，没有就新建）。

1. 把 `wpsmask_1.0.0` 整个文件夹复制进去。**目录名不要改**，`名字_版本号` 是加载依据。
2. 处理清单文件 `publish.xml`：
   - 目录里没有 → 把本仓库根目录的 `publish.xml` 复制进去；
   - 已经有（装过别的加载项）→ **不要覆盖**，只把这一行加进 `<jsplugins>` 里：

   ```xml
   <jsplugin name="wpsmask" type="et" url="wpsmask_1.0.0" version="1.0.0" enable="enable_dev" install="null" customDomain="" debug=""/>
   ```
3. 重启 WPS，打开任意表格，功能区出现「数据脱敏」选项卡。首次加载 WPS 可能弹信任提示，允许即可。

最终目录形态：

```
jsaddons\
├─ publish.xml
└─ wpsmask_1.0.0\
   ├─ index.html        入口页（WPS 启动时加载）
   ├─ main.js           串联脚本
   ├─ ribbon.xml        功能区定义
   ├─ js\
   │   ├─ utils.js      取应用对象、算资源路径
   │   ├─ aes.js        AES-128-CBC（纯 JS）
   │   ├─ engine.js     识别 / 生成 / 映射表 / 加解密落盘
   │   └─ ribbon.js     按钮回调、快捷映射与反映射
   └─ taskpane\
       ├─ index.html    映射面板
       ├─ taskpane.css
       └─ taskpane.js
```

> 已装 `wpsjs` 的话，也可以用它生成的 `publish.xml`，把上面的文件按同名替换进去；`wpsjs debug` 能直接带加载项启动 WPS。

### 开发时免复制

改仓库里的文件，不落到 `jsaddons` 就不生效。`tools/link-addon.ps1` 把那份复制过去的文件夹换成目录联接（junction），WPS 直接读工作区，改完只需重启 WPS：

```powershell
powershell -File tools/link-addon.ps1            # 建立联接；原文件夹留成 .bak-<时间戳>
powershell -File tools/link-addon.ps1 -Rollback  # 删掉联接，把备份还回去
```

目录联接不像软链接那样要管理员权限或开发者模式，普通文件接口也会跟着走；硬链接只能链文件，链不了文件夹。先关掉 WPS——加载项还加载着的时候，改名会失败。

## 三、使用

**面板方式**
1. 选中要处理的区域（整列 / 整行 / 任意块都行）。
2. 「映射面板」→「刷新选区」。每列一张卡片，自动判断成手机号/数字/文本，示例值就写在卡片头上，参数在下面按需展开。
3. 逐列核对「映射方式」和参数；「首行是表头」不勾就表示首行也参与映射。
4. 「映射并写入」→ 直接写回原区域。再点「反映射回原值」回到原始数据。

**重复映射不会叠加。** 已经是映射结果的单元格会被跳过，状态栏会点名跳过了哪几列。所以"先映射两列、再选全区映射"不会把那两列映射第二次；要基于当前值再映射一遍，先「反映射」。

**快捷方式**（不打开面板，用自动识别或上次记住的设置）
- 「快速映射」：直接处理当前选区。已映射的格子一样跳过；一格新数据都没有时，只提示、不写入。
- 「反映射」：直接还原当前选区。

**几个约定**
- 空白单元格不动。
- 「不处理」列完全跳过。
- 数值单元格读回的是序列号（日期就是数字），映射后仍是数字、格式不变；反映射按原类型写回。
- 数字映射保留原列的小数位；整数列生成整数。

## 四、映射表存在哪、加密到什么程度

- **位置**：本文档的隐藏工作表「脱敏映射表」。A1 是说明文字，A2 起是密文分片（每片 2 万字符，超出自动续行）。
- **算法**：AES-128-CBC + 随机 IV + PKCS#7，Base64 后加 `M1:` 前缀。同一个明文两次保存密文不同。
- **密钥**：`js/aes.js` 顶部 `KEY_TEXT`（16 字节）。
- **边界（必须知道）**：密钥随代码走，所以这是**混淆级**保护——挡住"打开文档就能看到原值"，挡不住"拿到这份加载项再反解"。要让外人彻底解不开，只能把密钥挪出文档（改成从本机配置或口令派生）。
- **改密钥的代价**：改完旧文档里的映射表全部解不开（面板会提示"解密失败"）。有存量文档时别动。
- **别忘了保存**：映射表跟着文档保存。映射完直接关窗口不保存，脱敏后的数据还在、映射表没了，就还原不回来了。

## 五、验证状态（重要）

**已在本地等价环境验证通过**（`node test/*.test.js`，用 mock 的 WPS 对象模型 + jsdom 跑真实面板页面）：

- AES 实现与 node `crypto` 双向逐字节一致（含空串、中文、emoji、5000 字符长文、篡改检测、IV 随机性）。
- 引擎：字段识别、1 对 1 与唯一性、区间容量不足报错、反映射精确还原（含类型与空值）、整列/整行裁剪、表头开关、密文落盘与重新读取、设置记忆、跨"重开文档"的映射稳定性。
- 面板：4 列卡片渲染、分布切换显示参数、类型切换重建卡片、执行映射、反映射、表头开关、清除映射表、无选区容错。
- 全部脚本语法检查、`ribbon.xml` XML 合法性检查。

**必须在真机跑一次才能确认的（技能库无实测依据，我按官方与社区可用样例写）**：

1. `publish.xml` 的字段与 `enable` 取值是否被你这版 WPS 接受 → 判断标准：功能区出现「数据脱敏」。
2. **任务窗格网页里 `window.Application` 是否注入**。这是最关键的一处：若面板显示"未取到 WPS 应用对象"，说明该版本任务窗格拿不到宿主对象，需要改成由宿主页代跑（`ribbon.js` 里已有同样的引擎调用，可作为临时出口：先用「快速映射/反映射」跑通）。
3. `CreateTaskPane` 是否接受 `file://` 形式的相对路径 URL。
4. `Worksheets.Add(undefined, 末表)` 的参数形式——代码里做了三级回退（`undefined` → `null` → 无参），三种都失败才会报错。
5. 隐藏工作表（`Visible = 2`）保存为 `.xlsx`/`.et` 后重开能否正常读回密文。
6. 大数据量（十万行级）的性能与界面卡顿。

## 六、常见问题

| 现象 | 排查 |
|---|---|
| 功能区没有「数据脱敏」 | 目录名必须是 `wpsmask_1.0.0`；`publish.xml` 的 `version`/`url` 要和目录名一致；改完必须重启 WPS |
| 面板空白、提示"未取到 WPS 应用对象" | 见上节第 2 条 |
| 重新映射某列却没有变化 | 该列已经是映射结果，被跳过了。要按当前值再映射一遍，先「反映射」 |
| 反映射只还原了一部分 | 选区要和映射时一致（同样起止行列）；或该列改过参数，旧映射仍在表里但反查会优先匹配当前参数的映射 |
| 数字列被显示成左对齐文本 | 目标单元格原本是文本格式，映射写入的数值保留了该格式，改单元格格式即可 |
| 提示"区间容量不足" | 整数区间里放不下这么多不同值（如 12 个不同金额却只给 1~5），放宽范围或改小数位 |
| 提示"解密失败" | `KEY_TEXT` 被改过，或「脱敏映射表」被手工编辑过 |
