# 数据脱敏映射 · WPS 表格加载项

*[English](README.md)*

选中一块区域，把里面的数据按规则替换成看似真实的假数据；原始值加密保存在文档中，随时可以一键还原。

## 一、需求对照

| 需求 | 实现方式 |
|---|---|
| 选区域 → 数据映射成随机数据 | 功能区「数据脱敏 → 映射面板」，或免界面的「快速映射」 |
| 1.1 一对一，同值同结果 | 映射表按 `原值 → 新值` 持久化；同一原值始终取同一条记录，不同原值分配到不同新值。碰撞时重试；容量不足时报错，不产生重复值 |
| 1.2 数字 / 文本两种映射值 | 「映射为」下拉：数字、文本、混合、不处理 |
| 1.2.1 数字可设参数，默认均匀 | 均匀分布（默认）、正态分布（均值/标准差，越界值折回区间）、指数分布（λ 控制衰减）；范围、小数位可改 |
| 1.2.2 文本 = 前缀 + 随机数字后缀 | 前缀默认取字段名（如「姓名37」），可改。后缀位数默认取能容纳本列非空单元格数的最小位数，另留 10% 余量：41 行客户名对应 2 位后缀（姓名37），不会写成「姓名0037」；可手动改为 1–8 位 |
| 1.3 自动识别字段名与类型 | 按值的 JS 类型判定数字或文本，整列归为数字/文本/混合；混合列数字换数字、文本换非数字文本。顺序见[识别顺序](docs/behavior_zh.md#识别顺序)。整列、整行选区先裁剪到实际有数据的范围再判定 |
| 2 一键反映射，映射关系加密 | 「反映射回原值」按加密表反查写回（保留数字/文本类型与空值；文本原值带宿主文本标记写回，`008081` 的前导零不丢、格式不变）。只还原这个加载项记录过「已映射」的区域：扩大选区不会误改没脱敏的列，连点第二次是空操作；同一个假值可能属于两个原值时，它不猜，留给用户并计数。映射表为 AES-128-CBC 密文，存放于隐藏工作表（[存储与加密边界](docs/storage_zh.md)） |
| 3 记住本文档上次的设置 | 每列的类型/分布/参数/前缀按字段名记在同一个加密块里，下次选中同一字段自动套用；数值区间只扩不缩（取上次区间与本批数据范围的并集），别的 sheet 同名列值域更宽也不会被旧区间卡住；「重新识别」忽略已记设置，重新检测 |
| 一眼看出哪些区域已映射 | 映射过的区域自动套一圈紫色虚线边框，不开面板也看得到；功能区的「全部加边框」「全部去边框」一键重画或去掉，只改外观、不动数据 |

识别、表头规则、提示消息与混合列见[脱敏行为](docs/behavior_zh.md)；隐藏映射表与加密边界见[存储](docs/storage_zh.md)。

## 二、安装（不需要 node 和 wpsjs，直接复制文件）

加载项目录在 `%APPDATA%\kingsoft\wps\jsaddons`（`Win+R` 输入 `%appdata%` → `kingsoft\wps\jsaddons`，没有就新建）。

不需要 Node.js、npm 或 `wpsjs`：加载项就是纯文件，下面三步就是全部安装过程。

1. 把 `wpsmask_1.0.0` 整个文件夹复制进去。**目录名不要改**，`名字_版本号` 是 WPS 识别加载项的依据。
2. 处理清单文件 `publish.xml`：
   - 目录里没有 → 把本仓库 `wps-mask-addon/publish.xml` 复制进去；
   - 已经有（装过别的加载项）→ **不要覆盖**，只把这一行加进 `<jsplugins>` 里：

   ```xml
   <jsplugin name="wpsmask" type="et" url="wpsmask_1.0.0" version="1.0.0" enable="enable" install="null" customDomain="" debug=""/>
   ```
3. 重启 WPS，打开任意表格，功能区出现「数据脱敏」选项卡。首次加载时 WPS 可能弹出信任提示，允许即可。

最终目录结构：

```
jsaddons\
├─ publish.xml
└─ wpsmask_1.0.0\
   ├─ index.html        入口页（WPS 启动时加载）
   ├─ main.js           串联脚本
   ├─ ribbon.xml        功能区定义
   ├─ images\           功能区图标：panel / quick / revert / mark / unmark，各带一份 @2x
   ├─ js\
   │   ├─ utils.js      取应用对象、算资源路径
   │   ├─ aes.js        AES-128-CBC（纯 JS）
   │   ├─ engine.js     识别 / 生成 / 映射表 / 加解密落盘
   │   └─ ribbon.js     按钮回调、快捷映射与反映射
   └─ taskpane\
       ├─ index.html    映射面板
       ├─ taskpane.css
       └─ taskpane.js
```

仓库 `assets/icons/` 里的 SVG 源文件不复制，只复制生成好的 PNG。如果已安装 `wpsjs`（不是必需），可以使用它生成的 `publish.xml`，按同名替换上述文件。

### 开发时免去复制

仓库里的改动只有复制到 `jsaddons` 后才会生效。`tools/link-addon.ps1` 把复制过去的文件夹替换为指向工作区的目录联接（junction），WPS 直接读取工作区文件，改完后只需重启 WPS：

```powershell
powershell -File tools/link-addon.ps1            # 建立联接；原文件夹保留为 .bak-<时间戳>
powershell -File tools/link-addon.ps1 -Rollback  # 删除联接，恢复备份
```

目录联接不需要管理员权限或开发者模式，硬链接只能指向文件、不能指向文件夹。操作前先关闭 WPS，否则加载项占用会导致改名失败。

## 三、使用

**面板方式。** 选中要处理的区域（整列 / 整行 / 任意块都行），打开「映射面板」：面板自动读取选区，选区变化时自动更新，不需要手动刷新。每列一张卡片，自动判断成数字/文本/混合，示例值显示在卡片头部，参数在下方按需展开；改过的卡片参数在选区刷新后按「工作表 + 列位置」保留。「映射并写入」直接写回原区域；「反映射回原值」只还原选区里这个加载项映射过的区域，它没写过的格子保持原样。

**表头行。** 「首行是表头」复选框决定第一行算不算数据：勾选时第一行永远不参与脱敏，并作为列名和文本前缀的来源；不勾时第一行就是数据。新选区会先猜一次——选区从第 1 行开始、首行有非空单元格且没有任何数字时复选框默认勾上，只看位置和类型，不看单元格文字。因此从第 1 行开始的全文本数据会被猜成表头；面板会提示，取消勾选即可。完整规则见[表头行](docs/behavior_zh.md#表头行)。

**重复映射不会叠加。** 只有落在映射写过的区域内、且值能通过映射表反查的单元格才会被跳过，状态栏会显示跳过的格数。反映射时这些记录会扣掉已还原的部分，所以第二次反映射没有东西可写。要基于当前值再映射一遍，先「反映射」。

**看哪些区域映射过。** 映射过的块在表格里自动套一圈紫色虚线边框，不开面板也看得到；功能区的「全部加边框」「全部去边框」一键重画或去掉，也会清掉旧失败尝试留下的紫线。区域与边框记录在映射时、写单元格之前的那一次保存里写进文档的隐藏表，反映射和边框都靠它找位置；关文档前保存才会跨会话保留。

**快捷方式。** 「快速映射」直接处理当前选区，已映射的格子一样跳过；没有新数据时只提示、不写入。「反映射」只还原选区里记录过的区域，没映射过的格子不动；没有可还原的内容时提示一句，不写任何单元格。

提示消息、通用约定与混合列见[脱敏行为](docs/behavior_zh.md)。

## 四、映射表与加密边界

- **原始值在哪**：隐藏工作表「脱敏映射表」里是 AES-128-CBC 密文，密钥是 `js/aes.js` 顶部的 `KEY_TEXT`；另有一列备份区保存上一份密文。
- **保存失败不等于写坏**：面板先保存映射表（备份、写入、读回并解密比对），再写单元格，所以保存失败时选举区一格都不动；主密文损坏时要么用备份恢复，要么明确报错，绝不会被当成「新文档」。
- **保护边界**：密钥跟代码一起发出去，这只是混淆。任何持有这一版加载项的人都能不经口令点「反映射」；卸载、换机、把文档转给别人，界面上就没有还原入口，但 WPS 的备份中心、历史版本与撤销栈里可能仍留着脱敏前的值。
- **存不下来的东西**：公式单元格只还原数值、不还原公式；隐藏表挡不住宏；最多记住最近 200 个已映射区域；只读文档在保存映射表之前就会被拒绝。删除映射表时会先恢复边框，并列出恢复失败或已不存在的工作表，然后照常删表。

算法、失败文案、谁能还原与完整限制清单见[存储](docs/storage_zh.md)。

## 五、验证

```sh
# 在仓库根目录执行
npm install                 # 安装 jsdom，面板与辅助函数测试需要
npm test                    # 按顺序跑引擎、AES、功能区、面板、辅助函数、桥六个测试
```

本地测试全部跑在 mock 的 WPS 对象模型和 jsdom 里的真实面板页面上。真机（WPS 表格 12.1.0.29161）上，功能区、面板宿主对象、`CreateTaskPane` 收 `file://`、隐藏表存盘重开、边框颜色的打包字节序通过；合并单元格与只读文档需要当心。单次保存流程在本地 mock 上十万行实测 8.1 秒（旧的两保存流程 21.1 秒），真机尚未重测。测试清单、真机实测表、复现方式、常见问题与缺失的参考资料见[验证状态](docs/verification_zh.md)。
