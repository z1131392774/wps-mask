# 数据脱敏映射 · WPS 表格加载项

*[English](README.md)*

选中一块区域，把里面的数据按规则替换成看似真实的假数据；原始值加密保存在文档中，随时可以一键还原。

---

## 一、需求对照

| 需求 | 实现方式 |
|---|---|
| 选区域 → 数据映射成随机数据 | 功能区「数据脱敏 → 映射面板」，或免界面的「快速映射」 |
| 1.1 一对一，同值同结果 | 映射表按 `原值 → 新值` 持久化；同一原值始终取同一条记录，不同原值分配到不同新值。碰撞时重试；容量不足时报错，不产生重复值 |
| 1.2 数字 / 文本两种映射值 | 「映射为」下拉：手机号、数字、文本、混合、不处理 |
| 1.2.1 数字可设参数，默认均匀 | 均匀分布（默认）、正态分布（均值/标准差，越界值折回区间）、指数分布（λ 控制衰减）；范围、小数位可改 |
| 1.2.2 手机号必须合法 | 从真实号段（130–199）取 3 位前缀，加 8 位随机数字，保证 `1[3-9]` 开头共 11 位，列内不重复、不与原值相同 |
| 1.2.3 文本 = 前缀 + 随机数字后缀 | 前缀默认取字段名（如「姓名37」），可改。后缀位数默认取能容纳本列非空单元格数的最小位数，另留 10% 余量：41 行客户名对应 2 位后缀（姓名37），不会写成「姓名0037」；可手动改为 1–8 位 |
| 1.3 自动识别字段名与类型 | ①字段名命中 手机/电话/phone/tel 等 → 手机号；②≥60% 数据形如手机号 → 手机号；③≥80% 是数值 → 数字；④其余 → 文本（前缀取字段名）。整列、整行选中都能正确取字段名 |
| 2 一键反映射，映射关系加密 | 「反映射回原值」按加密表反查写回（保留数字/文本类型与空值）；映射表为 AES-128-CBC 密文，存放于隐藏工作表 |
| 3 记住本文档上次的设置 | 每列的类型/分布/参数/前缀按字段名记在同一个加密块里，下次选中同一字段自动套用；数值区间只扩不缩（取上次区间与本批数据范围的并集），别的 sheet 同名列值域更宽也不会被旧区间卡住；「重新识别」忽略已记设置，重新检测 |

## 二、安装（不需要 node 和 wpsjs，直接复制文件）

加载项目录在 `%APPDATA%\kingsoft\wps\jsaddons`（`Win+R` 输入 `%appdata%` → `kingsoft\wps\jsaddons`，没有就新建）。

1. 把 `wpsmask_1.0.0` 整个文件夹复制进去。**目录名不要改**，`名字_版本号` 是 WPS 识别加载项的依据。
2. 处理清单文件 `publish.xml`：
   - 目录里没有 → 把本仓库根目录的 `publish.xml` 复制进去；
   - 已经有（装过别的加载项）→ **不要覆盖**，只把这一行加进 `<jsplugins>` 里：

   ```xml
   <jsplugin name="wpsmask" type="et" url="wpsmask_1.0.0" version="1.0.0" enable="enable" install="null" customDomain="" debug=""/>
   ```
3. 重启 WPS，打开任意表格，功能区出现「数据脱敏」选项卡。首次加载时 WPS 可能弹出信任提示，允许即可。

最终目录结构：

```
jsaddons\
├─ publish.xml
└─ wpsmask_1.0.0\
   ├─ index.html        入口页（WPS 启动时加载）
   ├─ main.js           串联脚本
   ├─ ribbon.xml        功能区定义
   ├─ js\
   │   ├─ utils.js      取应用对象、算资源路径
   │   ├─ aes.js        AES-128-CBC（纯 JS）
   │   ├─ engine.js     识别 / 生成 / 映射表 / 加解密落盘
   │   └─ ribbon.js     按钮回调、快捷映射与反映射
   └─ taskpane\
       ├─ index.html    映射面板
       ├─ taskpane.css
       └─ taskpane.js
```

> 如果已安装 `wpsjs`，可以使用它生成的 `publish.xml`，按同名替换上述文件；`wpsjs debug` 可以直接加载加载项并启动 WPS。

### 开发时免去复制

仓库里的改动只有复制到 `jsaddons` 后才会生效。`tools/link-addon.ps1` 把复制过去的文件夹替换为指向工作区的目录联接（junction），WPS 直接读取工作区文件，改完后只需重启 WPS：

```powershell
powershell -File tools/link-addon.ps1            # 建立联接；原文件夹保留为 .bak-<时间戳>
powershell -File tools/link-addon.ps1 -Rollback  # 删除联接，恢复备份
```

目录联接不需要管理员权限或开发者模式，普通文件接口也能正常访问；硬链接只能指向文件，不能指向文件夹。操作前先关闭 WPS，否则加载项占用会导致改名失败。

## 三、使用

**面板方式**
1. 选中要处理的区域（整列 / 整行 / 任意块都行）。
2. 打开「映射面板」：面板自动读取选区，选区变化时自动更新，不需要手动刷新；未选中区域时只显示一行提示，工具栏不显示，写入按钮置灰。
3. 每列一张卡片，自动判断成手机号/数字/文本：示例值显示在卡片头部，参数在下方按需展开。逐列核对「映射方式」和参数；「首行是表头」不勾就表示首行也参与映射。
4. 「映射并写入」→ 直接写回原区域。再点「反映射回原值」回到原始数据。

**重复映射不会叠加。** 已经是映射结果的单元格会被跳过，状态栏会显示跳过的格数。所以"先映射两列、再选全区映射"不会把那两列映射第二次；要基于当前值再映射一遍，先「反映射」。

**快捷方式**（不打开面板，用自动识别或上次记住的设置）
- 「快速映射」：直接处理当前选区。已映射的格子一样跳过；没有新数据时只提示、不写入。成功只在底部状态栏报一句格数，几秒后消失，不弹窗；失败才弹窗。
- 「反映射」：直接还原当前选区。

**通用约定**
- 空白单元格不动。
- 「不处理」列完全跳过。
- 数值单元格读回的是序列号（日期也是数字），映射后仍是数字、格式不变；反映射按原类型写回。
- 数字映射保留原列的小数位；整数列生成整数。

**混合列（手机、邮箱、固话、工号混在同一列）**
账号列经常同时包含多种格式。把这一列设为「混合」后，每个单元格按自身形态分别处理：

| 原值形态 | 映射成 |
|---|---|
| 手机号 | 另一个合法手机号 |
| 邮箱 | `u` + 6 位数字，**域名保留**（`li.na@corp.com` → `u005288@corp.com`）|
| 固话 | 区号、分隔符、位数、分机号都保留（`020-88997766` → `020-41283071`）|
| 纯数字 | 同位数数字，前导零保留（`000123` → `000233`）|
| 字母数字账号 | 逐字替换同形态（`kf_2024_001` → `ud_9309_739`）|
| 其余（中文等）| 回落到「字段名 + 数字」 |

一对一映射仍然成立：原值是唯一的键，反映射与新值的生成形态无关。注意两点：邮箱域名会保留（`@corp.com` 依然可见）；过短的账号（如 `a1`）可用的同形态组合有限，用尽时会报错，不会生成重复值。

## 四、映射表的存储位置与加密边界

- **位置**：本文档的隐藏工作表「脱敏映射表」。A1 是说明文字，A2 起是密文分片（每片 2 万字符，超出自动续行）。
- **算法**：AES-128-CBC + 随机 IV + PKCS#7，Base64 后加 `M1:` 前缀。同一明文两次保存的密文不同。
- **密钥**：`js/aes.js` 顶部 `KEY_TEXT`（16 字节）。
- **保护边界**：密钥写在代码里，因此这只是一种混淆手段：能防止直接打开文档查看原值，但无法防止持有这份加载项的人反向解密。如果需要让外部人员无法解密，必须把密钥移出文档，改为从本机配置或口令派生。
- **假值还能看出什么**：数字列在区间内随机取值，区间按数据范围外再留 10% 余量（如 20~43），所以假值不是原列的重排——排序后的多重集、频次分布都与原列不同。但区间的最小/最大值、行数、空值位置、行顺序仍然可见，文本与手机号列的位数、形态也照旧保留。
- **修改密钥的代价**：修改后，旧文档中的映射表全部无法解密（面板提示"解密失败"）。已有文档包含映射表时不要修改。
- **务必保存文档**：映射表随文档一起保存。映射后不保存就关闭窗口，脱敏数据仍在，但映射表丢失，数据将无法还原。

## 五、验证状态

**已在本地环境验证通过**（`node test/*.test.js`，用 mock 的 WPS 对象模型 + jsdom 运行真实面板页面）：

- AES 实现与 node `crypto` 双向逐字节一致（含空串、中文、emoji、5000 字符长文、篡改检测、IV 随机性）。
- 引擎：字段识别、1 对 1 与唯一性、容量不足报错、反映射精确还原（含类型与空值）、整列/整行裁剪、表头开关、密文落盘与重新读取、设置记忆、跨"重开文档"的映射稳定性。
- 混合模式：五种形态各自按原样替换（域名保留、区号保留、位数与前导零保留、字母逐字替换），十个混合值逐个精确还原；纯手机号/纯数字/纯文本列仍按原规则识别。
- 面板：4 列卡片渲染、分布切换显示参数、类型切换重建卡片、执行映射、反映射、表头开关、清除映射表、无选区容错。
- 全部脚本语法检查、`ribbon.xml` XML 合法性检查。

**尚未在真机验证的条目**（本地文档没有这些接口的实测资料，实现依据官方和社区样例）：

1. `publish.xml` 的字段与 `enable` 取值是否被当前 WPS 版本接受 → 判断标准：功能区出现「数据脱敏」。
2. **任务窗格网页里 `window.Application` 是否注入**。这是最关键的一项：如果面板显示"未取到 WPS 应用对象"，说明该版本的任务窗格无法获取宿主对象，需要改为由宿主页执行（`ribbon.js` 中已有相同的引擎调用，可暂时使用「快速映射/反映射」完成操作）。
3. `CreateTaskPane` 是否接受 `file://` 形式的相对路径 URL。
4. `Worksheets.Add(undefined, 末表)` 的参数形式——代码里做了三级回退（`undefined` → `null` → 无参），三种都失败才会报错。
5. 隐藏工作表（`Visible = 2`）保存为 `.xlsx`/`.et` 后重开能否正常读回密文。
6. 大数据量（十万行级）的性能与界面卡顿。

## 六、常见问题

| 现象 | 排查 |
|---|---|
| 功能区没有「数据脱敏」 | 目录名必须是 `wpsmask_1.0.0`；`publish.xml` 的 `version`/`url` 要和目录名一致；改完必须重启 WPS |
| 面板空白、提示"未取到 WPS 应用对象" | 见上节第 2 条 |
| 重新映射某列却没有变化 | 该列已经是映射结果，被跳过了。要按当前值再映射一遍，先「反映射」 |
| 反映射只还原了一部分 | 选区要和映射时一致（同样起止行列）；或该列改过参数，旧映射仍在表里，但反查会优先匹配当前参数的映射 |
| 数字列被显示成左对齐文本 | 目标单元格原本是文本格式，映射写入的数值保留了该格式，改单元格格式即可 |
| 提示"装不下 N 个不同值" | 整数区间里放不下这么多不同值（如 12 个不同金额却只给 1~5）。自动映射会按数据范围扩区间，正常不会出现；只有你手改窄了区间才会，放宽范围或改小数位 |
| 提示"解密失败" | `KEY_TEXT` 被改过，或「脱敏映射表」被手工编辑过 |
| 混合列里某个值被映射成了「字段名+数字」 | 它不属于那五种形态（中文、只有一个字符、`2024abc` 这类数字开头的编码、或带 `_ . -` 和空格之外的符号），因此使用文本兜底——兜底同样一对一，也能还原 |

## 七、缺失的参考资料（这套加载项 API 目前没有任何文档）

按重要性排序。补齐后，上面标注"待验证"的条目可以改为实测结论：
